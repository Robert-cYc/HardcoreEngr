Claude Code Skill、MCP 與 Plugin 深度解析

2026-09-23·30 分鐘閱讀
Claude Code Skill MCP Plugin AI 開發工具
🎯 重點摘要： 本文深入解析 Claude Code 三大擴展機制：
  ① Skill — 把你常做的 SOP 寫成一鍵指令（/code-review、/bug-fix...）
  ② MCP — 用開放標準連接外部系統（資料庫、GitHub、瀏覽器、自訂 API...）
  ③ Plugin — 把 Skill、MCP、Hook 打包成一個可分享的完整套件

嘿，如果你已經用 Claude Code 一陣子了，應該已經感受到它不只是個「聊天寫程式」的工具。真正讓它變強的，其實是這三個擴展機制：Skill、MCP、Plugin。這篇文章不講廢話，直接帶你從零到實戰，讓 Claude Code 從「好用的助手」進化成「你專屬的工程平台」。

為什麼要學這三個？

簡單說：沒有它們，Claude Code 就像一把瑞士刀，功能齊全但還是得靠你手動操作。有了它們，它就像一個已經熟悉你專案慣例、知道怎麼查資料庫、會自動執行工作流程的工程師。你只需要下指令，它自己搞定。

這三個機制各自負責不同的事：

  • Skill 管「流程」——你重複做過的步驟
  • MCP 管「連接」——外部資料與服務
  • Plugin 管「打包」——把前兩個加上 Hook 整包分享給團隊
💡 小提醒：這三個機制可以單獨用，也可以組合。你今天只想做一個自動 code review 流程，那就先學 Skill；想接資料庫，就學 MCP。別一次全上，先解決你最痛的那個點。

Skill — 把重複的 SOP 變成一鍵指令

什麼是 Skill？

你有沒有遇過這種情況：每次改完 code 之後，都要手動跑 git diff、檢查 lint、寫測試、跑 CI... 這些步驟每次都一樣，但 Claude 不一定記得全部要做。Skill 就是把這些固定流程寫成一個檔案，然後用 /skill-name 一鍵觸發。

它的本質就是一個 可重用的 prompt 模板，存在專案目錄下的 .claude/skills/ 資料夾中。

Skill 檔案結構

每個 Skill 就是一個資料夾，裡面只有一個檔案 SKILL.md：

.claude/
├── skills/
│   ├── code-review/
│   │   └── SKILL.md      # 觸發方式：/code-review
│   ├── bug-fix/
│   │   └── SKILL.md      # 觸發方式：/bug-fix
│   └── generate-tests/
│       └── SKILL.md      # 觸發方式：/generate-tests

注意：資料夾名稱要跟 SKILL.md 前面的 name: 完全一致，不然 Claude 找不到。

建立第一個 Skill：實戰範例

假設你想建立一個「自動審查修改檔案」的 Skill，讓 Claude 每次收到 /code-review 時，會自動：

  1. 列出所有修改過的檔案
  2. 逐一檢查每個檔案的 diff
  3. 分類問題（Critical / Warning / Info）
  4. 產出一份格式化報告

在 .claude/skills/code-review/SKILL.md 中寫入：

---
name: code-review
description: 對專案的變更檔案進行程式碼品質審查
---

# /code-review — 程式碼品質審查

## 目的
對專案中的 changed files 進行審查，包含：
- Bug 檢測
- 效能瓶頸
- 安全漏洞
- 可讀性問題

## 操作指令
1. 執行 `git diff main --name-only` 列出修改檔案
2. 逐一檢視：`git diff main -- <file>`
3. 分類問題：Critical（可能崩潰/安全漏洞）、Warning（效能/優化建議）、Info（可讀性改善）
4. 撰寫格式化報告
5. 若輸入 `/code-review high`，使用更嚴格標準
6. 若輸入 `/code-review --fix`，在報告後自動修復可修復問題

存檔後重新啟動 Claude（或執行 /exit 再進來），輸入 /code-review 就可以看到 Skill 生效了。如果沒出現，執行 /doctor 檢查配置是否有錯。

💡 小技巧：你可以在 Skill 前面的 frontmatter 加 allowed-tools 來限制這個 Skill 可以呼叫哪些工具，增加安全性。例如只允許 Read、Edit，不允許 Bash 執行危險指令。

全域 Skill — 跨專案共用

如果你有一些個人工作流（例如每日報告、提交輔助），不想每個專案都複製一份，可以把 Skill 放到家目錄下：

~/.claude/
└── skills/
    ├── daily-report/
    │   └── SKILL.md      # /daily-report
    └── commit-helper/
        └── SKILL.md      # /commit-helper

這樣所有專案都能直接用 /daily-report，非常方便。

MCP — 讓 Claude Code 連接外部世界

什麼是 MCP？

MCP (Model Context Protocol) 是 Anthropic 推出的開放標準，讓 Claude Code 可以連接到外部資料來源與服務。簡單說，就是讓 Claude 能「讀」和「操作」你專案之外的東西。

它提供三種能力：

能力說明使用場景
Resources可讀取的資料（檔案內容、API 回應）自動讀取設計文件、API 文件
Tools可呼叫的函數（需使用者批准）更新 GitHub Issue、查詢資料庫
Prompts預寫的 prompt 模板透過特定指令觸發

如何設定 MCP Server

最常用的方式是在專案根目錄建立 .mcp.json 檔案：

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/username/project"],
      "env": { "PATH": "/usr/local/bin" }
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_xxxxx" }
    },
    "sqlite": {
      "command": "uv",
      "args": ["--directory", "/path/to/sqlite-mcp", "run", "sqlite.py"],
      "env": { "SQLITE_PATH": "/path/to/app.db" }
    }
  }
}
⚠️ 安全提醒：.mcp.json 會被 Git 追蹤，千萬別把 API Token 直接寫在裡面。對於敏感憑證，推薦用 claude mcp login 進行 OAuth 授權，或把檔案加入 .gitignore。

實戰範例：接上 SQLite 資料庫

假設你有一個 SQLite 資料庫 /path/to/app.db，想讓 Claude 直接查詢內容。步驟非常簡單：

步驟 1 — 建立 .mcp.json

{
  "mcpServers": {
    "sqlite": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-sqlite", "/path/to/app.db"]
    }
  }
}

步驟 2 — 啟動 Claude Code 並使用

啟動 Claude 後，它會自動掃描 .mcp.json 並詢問是否信任這些 Server。選擇信任後，你就可以直接對 Claude 說：

查詢 users 資料表的所有欄位

Claude 會透過 MCP Server 直接執行 SQL 並回傳結果，完全不用你手動打 SQL！

常用 MCP Server 快速參考

Server 名稱用途安裝指令
@modelcontextprotocol/server-filesystem本地檔案系統存取npx -y ... <path>
@modelcontextprotocol/server-memory記憶持久化npx -y ...
@modelcontextprotocol/server-githubGitHub API 操作npx -y ...
@modelcontextprotocol/server-sqliteSQLite 資料庫查詢npx -y ...
@modelcontextprotocol/server-fetchHTTP 網頁抓取npx -y ...
@modelcontextprotocol/server-brave-searchBrave 搜尋npx -y ...
📚 如果現有 Server 不符合需求，可以自己寫一個。MCP 提供 Python、TypeScript、Java、C# 多語言 SDK。官方教學：Building Your First MCP Server。

CLI 管理指令

在 Claude Code session 中，你可以用以下指令管理 MCP：

命令說明範例
claude mcp列出所有連線狀態claude mcp
claude mcp reconnect <name>重新連線指定 Serverclaude mcp reconnect github
claude mcp disable <name>禁用指定 Serverclaude mcp disable sqlite
claude mcp disable all禁用所有 Server—
claude mcp login <name>執行 OAuth 授權流程claude mcp login sentry
claude mcp logout <name>清除 OAuth 憑證claude mcp logout sentry

Plugin — 把能力打包成完整套件

什麼是 Plugin？

Plugin 是 Claude Code 最高層的封裝單位。它把 Skill、MCP Server、Hooks、Subagents 與 Slash Commands 打包成一個可安裝的套件，透過 marketplace 安裝：

/plugin marketplace add <repo-url>
/plugin install <plugin-name>

對團隊來說，這招非常省事：把共用的 code review 流程（Skill）、內部 API 的 MCP Server、強制執行的 Hooks 打包成一個 Plugin，新人裝完就等於完成了整套環境建置。

Plugin 結構

一個典型的 Plugin 目錄結構可能長這樣：

my-team-plugin/
├── plugin.json              # Plugin 設定
├── skills/
│   └── team-review/
│       └── SKILL.md
├── mcp/
│   └── .mcp.json
├── hooks/
│   └── hooks.json
└── subagents/
    └── security-checker.md
💡 Plugin 的價值不只是「方便安裝」，更重要的是「統一標準」。當整個團隊都用同一個 Plugin，你不用擔心每個人的 Skill 版本不同、Hook 設定不一致，所有人都在同一套規範下工作。

三者關係：選擇心法

這三個機制常常讓人搞混，這裡給你一個簡單的選擇心法：

機制觸發方式解決什麼問題配置位置
Skill使用者輸入 /指令固定 SOP、可重用工作流.claude/skills/
MCP模型依需求呼叫工具連接外部系統與資料源.mcp.json
Hook事件點自動觸發強制自動化（格式化、攔截、通知）.claude/settings.json
Plugin透過 /plugin 安裝打包以上所有能力，團隊共用marketplace repo

一句話記住：要連外部服務用 MCP；要把重複流程變一鍵用 Skill；要「一定會執行」的自動化用 Hook；要分享給團隊就用 Plugin。

實戰組合：一個完整工作流範例

假設你在一個團隊裡，想建立一套完整的開發輔助系統。你可以這樣組合：

場景：自動審查 + 資料庫查詢 + 團隊分享

  1. 建立 Skill：在專案中建立 .claude/skills/code-review/SKILL.md，定義審查流程
  2. 添加 MCP：在 .mcp.json 中配置 SQLite Server，讓 Claude 能直接查專案資料
  3. 配置 Hook：在 .claude/settings.json 中設定 PostToolUse，自動格式化修改過的檔案
  4. 打包 Plugin：把以上內容整理成一個 Plugin，發布到團隊 marketplace
  5. 團隊安裝：團隊成員只需要執行 /plugin install team-dev-kit，全部功能立即可用
🎯 快速上手建議：別一次全上！先從最痛的那個開始——如果你常做 code review，先寫 Skill；如果你常查資料庫，先接 MCP。等一個機制熟悉了，再加下一個。記住：先解決問題，再追求完美。

常見問題與疑難排解

Skill 沒出現怎麼辦？

最常見的三個原因：

  1. 資料夾名稱與 frontmatter 的 name 不一致
  2. 忘記加 --- 前後的分隔線
  3. 沒有重新啟動 Claude session（或執行 /skills 確認列表）

執行 /doctor 可以快速診斷配置問題。

MCP Server 連接失敗

檢查步驟：

  1. 確認 .mcp.json 語法正確（用 JSON 驗證工具）
  2. 執行 claude mcp 看連線狀態
  3. 確認 command 和 args 路徑正確，特別是絕對路徑
  4. 確認環境變數（特別是 Token）已正確設定

Plugin 安裝後功能沒生效

通常是因為 Plugin 需要重新啟動 Claude session 才能完全載入。執行 /plugin list 確認安裝狀態，再用 /exit 重啟。

總結：從助手到工程平台的進化路徑

Claude Code 的強大之處，不只是對話編程的能力，而是這三層擴展機制：MCP 打通外部資料源，Skill 沉澱你的工作流，Hook 保證自動化必然執行，Plugin 負責打包分享。當你把這四個湊在一起，Claude Code 就從一個聊天助手，真正變成一個客製化的工程平台。

記住一句話：先解決最痛的那一個，不要一次全上。 你的第一個 Skill、第一個 MCP Server、第一個 Plugin，會讓你感受到這個平台真正的力量。

🎯 最終建議：今天就做一件事——在你的專案中建立第一個 Skill（哪怕只是「自動格式化」），或接上第一個 MCP Server（哪怕只是檔案系統）。那個成功的瞬間，你就會明白為什麼這麼多人說 Claude Code 改變了他們的工作方式。
