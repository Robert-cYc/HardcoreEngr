1. 誕生緣起與核心定位

在 PC 硬體工程師、超頻玩家、自組伺服器系統管理員或物聯網 (IoT) 儀表板開發者的日常工作中，精準、即時、輕量且能被程式化讀取的硬體監測數據是一切調校與保護機制的基石。

長久以來，Windows 平台上雖然有許多知名的監控工具，但多數面臨以下瓶頸：

  • Open Hardware Monitor (OHM)：曾是開源硬體監控的黃金標準，但其維護節奏自 2016 年後大幅放緩，無法及時支援 Intel 12/13/14 代混合架構 (P-Core/E-Core)、AMD AM5 Zen 4/5 架構、NVIDIA RTX 40/50 系列顯卡及新型 Super I/O 監控晶片。
  • HWiNFO64 & AIDA64：功能極度強大、偵測極為完整，但本質為商業閉源軟體。商業環境使用需採購授權，且官方 Shared Memory 或 API 介面在免費版有 12 小時重啟限制或需專業版授權，對自建自動化服務非常不友善。
  • 原廠驅動軟體 (如 Corsair iCUE、NZXT CAM、ASUS Armoury Crate)：體積龐大臃腫，動輒佔用數百 MB 記憶體與 3%~8% CPU 使用率，甚至存在各家感測器互斥搶占 LPC 總線的衝突問題。

為了解決上述痛點，開源社群以 Mozilla Public License 2.0 (MPL 2.0) 協議分支 (Fork) 出 Libre Hardware Monitor (LHM)。它保留了極簡無廣告的純淨傳統，並由全球開源社群積極更新驅動程式與晶片定址表，成為目前 Windows 平台上生態最開放、二次開發最便利、授權最友善的開源硬體遙測基礎設施。

2. 底層運作機制硬核剖析：從 Ring 3 穿透至 Ring 0

許多初學者最常問的問題是：「為什麼隨便寫一個 C# 或 Python 程式讀不到 CPU 核心溫度？為什麼 Libre Hardware Monitor 必須以系統管理員權限執行？」

答案隱藏在現代 x86/x64 處理器與 Windows 作業系統的硬體特權等級 (Privilege Rings) 與硬體架構中：

2.1 CPU 核心溫度讀取：MSR 暫存器與 DTS 計算公式

現代 Intel 與 AMD 處理器並不是依靠外部溫度計測量晶圓溫度，而是在每個核心內部整合了數位熱敏感測器 (Digital Thermal Sensor, DTS)。這個數值儲存在 CPU 特定的 Model-Specific Registers (MSR) 中。

在 x86 架構下，讀取 MSR 必須調用組合語言特權指令 RDMSR (Opcode: 0F 32)。這條指令只能在 Ring 0 核心模式下執行，若在 Ring 3 執行會直接觸發一般保護錯誤 (General Protection Fault, #GP)。

LHM 驅動程式深入 CPU 暫存器，讀取過程如下：

  1. 讀取 IA32_TEMPERATURE_TARGET (MSR 0x1A2)，獲取處理器的最大結溫（$T_{jmax}$，通常在 100°C ~ 115°C 之間）。
  2. 讀取各核心的 IA32_THERM_STATUS (MSR 0x19C)，其中第 16 到 22 位元儲存的是距離 $T_{jmax}$ 的負偏移量（$\Delta T$）。
  3. 依據硬體規範精確計算各核心即時溫度： $$T_{\text{core}} = T_{jmax} - \text{Reading}_{\text{DTS}}$$

2.2 主機板電壓與風扇轉速：Super I/O 晶片與 LPC/eSPI 總線通訊

主機板上的 CPU 風扇轉速 (RPM)、機殼風扇、+12V / +5V / +3.3V 電壓軌以及主機板各部位溫度，是由主機板上的 Super I/O (SIO) 晶片（如 Nuvoton NCT67xx 系列、ITE IT86xx 系列、Fintek）負責採樣。

Super I/O 晶片掛載在主機板的 LPC (Low Pin Count) 或 eSPI 總線上，作業系統與其通訊需透過 I/O 連接埠定址：

  • 索引連接埠 (Index Port)：通常為 0x2E 或 0x4E。
  • 資料連接埠 (Data Port)：通常為 0x2F 或 0x4F。

LHM 會向索引埠寫入晶片的邏輯裝置編號 (Logical Device Number, LDN)，解鎖硬體監控模組 (Hardware Monitor Device)，接著使用 IN / OUT 指令讀取內部暫存器。風扇轉速則是透過計算風扇霍爾感測器產生的脈衝間隔轉速計數器（Tachometer Counter）反推得出：

$$RPM = \frac{60 \times f_{\text{internal}}}{Count \times PulsesPerRevolution}$$

2.3 顯示卡與儲存裝置監控介面

  • GPU 遙測：LHM 不需要驅動直接操作 PCI 空間，而是調用原廠提供的使用者模式動態函式庫——NVIDIA 呼叫 nvapi64.dll (NVAPI)，AMD 呼叫 atidxx64.dll / ADLX 介面，讀取 GPU 核心溫度、Hot Spot 結溫、顯存 VRAM 溫度、風扇轉速百分比與 Board Power 瓦數。
  • NVMe SSD / SATA 硬碟：透過 Windows Win32 API CreateFile 開啟磁碟實體控制把柄（如 \\.\PhysicalDrive0），並發送 DeviceIoControl 搭配 SMART_RCV_DRIVE_DATA 或 IOCTL_STORAGE_PROTOCOL_COMMAND，解析 S.M.A.R.T. 屬性表與 NVMe Log Page 0x02，獲取複合溫度 (Composite Temperature) 與可用備用空間壽命百分比。

4. 基礎安裝、介面功能與開機常駐無感運行

4.1 下載與正確解壓縮

  1. 前往 Libre Hardware Monitor GitHub 官方 Releases 下載最新發布的 LibreHardwareMonitor-net472.zip。
  2. 解除安全鎖定：在下載的 ZIP 檔案上點擊右鍵 → 內容 → 勾選最下方的 「解除封鎖 (Unblock)」，然後按確定（防止 Windows SmartScreen 封鎖內部 DLL）。
  3. 解壓縮至不會被輕易移動的固定目錄，建議放在 C:\Program Files\LibreHardwareMonitor\ 或 C:\Tools\LibreHardwareMonitor\。
  4. 右鍵點擊 LibreHardwareMonitor.exe，選擇「以系統管理員身分執行」。

4.2 核心介面配置與功能

  • 樹狀階層視圖 (Hierarchy View)：展開各節點即可查看各零件的即時值 (Value)、最小值 (Min) 與最大值 (Max)。在感測器上點右鍵可選擇 Show in Tray（常駐系統匣即時顯示小圖示）或 Show in Plot（繪製即時折線圖）。
  • 懸浮小工具 (Show Desktop Gadget)：點選選單 View → Show Gadget，即可在桌面上顯示一個半透明置頂懸浮面板，隨意拖拉放置你關心的 CPU 溫度或 GPU 負載。

4.3 生產級開機無感常駐：跳過 UAC 彈窗的「工作排程器」設定法

很多工程師發現：如果只在軟體內部勾選 Options → Run On Windows Startup，每次重開機登入 Windows 都會跳出煩人的 「使用者帳戶控制 (UAC)」黃色確認彈窗，甚至導致自動化腳本卡死在登入階段。

最佳實踐解法：使用 Windows 工作排程器 (Task Scheduler) 設定以「最高權限」自動啟動：

# 以系統管理員權限打開 PowerShell，執行以下指令自動註冊排程任務
$Action = New-ScheduledTaskAction -Execute "C:\Tools\LibreHardwareMonitor\LibreHardwareMonitor.exe"
$Trigger = New-ScheduledTaskTrigger -AtLogOn
$Principal = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType Interactive -RunLevel Highest
$Settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -ExecutionTimeLimit 0

Register-ScheduledTask -TaskName "LibreHardwareMonitor_AutoStart" -Action $Action -Trigger $Trigger -Principal $Principal -Settings $Settings

這樣一來，無論何時開機登入，軟體都會在背景以系統管理員最高權限無縫啟動，完全不會彈出 UAC 警告！

5. HTTP JSON API 深度實戰與跨語言串接

5.1 啟用 Web Server 與網路連線綁定

  1. 在軟體選單點擊 Options → Remote Web Server → 點擊 Run。

5.3 跨語言實戰範例 1：現代前端 JavaScript 非同步輪詢

以下程式碼展示如何在自製網頁儀表板中，透過遞迴函數精準搜尋感測器並提取數值：

// 遞迴搜尋樹狀結構中的指定感測器
function findSensor(node, targetText, parentCategory = null) {
  if (node.Text === targetText && (!parentCategory || node._category === parentCategory)) {
    return node;
  }
  if (node.Children) {
    for (const child of node.Children) {
      if (['Temperatures', 'Loads', 'Powers', 'Fans'].includes(node.Text)) {
        child._category = node.Text;
      } else if (node._category) {
        child._category = node._category;
      }
      const found = findSensor(child, targetText, parentCategory);
      if (found) return found;
    }
  }
  return null;
}

// 定時抓取並更新畫面
async function pollHardwareTelemetry() {
  try {
    const res = await fetch('http://localhost:8085/data.json');
    const root = await res.json();
    
    // 取得 CPU Package 溫度
    const cpuTempNode = findSensor(root, 'CPU Package', 'Temperatures');
    // 取得 CPU 總負載
    const cpuLoadNode = findSensor(root, 'CPU Total', 'Loads');

    if (cpuTempNode) {
      console.log(`即時 CPU 溫度: ${cpuTempNode.Value} (峰值: ${cpuTempNode.Max})`);
      document.getElementById('cpu-temp').innerText = cpuTempNode.Value;
    }
  } catch (err) {
    console.warn('無法連線至 Libre Hardware Monitor Remote Server:', err);
  }
}

setInterval(pollHardwareTelemetry, 1000);

5.4 跨語言實戰範例 2：Python 自動化監控與高溫蜂鳴報警腳本

這段 Python 腳本會自動扁平化 JSON 樹，以乾淨的終端機即時儀表印出當前 CPU/GPU 狀態，並在溫度超過警戒值時發出系統蜂鳴聲或警報：

import time
import requests
import winsound  # Windows 原生發聲模組

LHM_API_URL = "http://localhost:8085/data.json"
TEMP_THRESHOLD = 85.0  # 超溫警報門檻 (攝氏)

def flatten_sensors(node, hardware_name="System"):
    """遞迴攤平 LHM 樹狀結構為清單字典"""
    results = []
    current_hw = hardware_name
    
    # 若當前節點帶有圖示或為頂層裝置，更新硬體名稱
    if "ImageURL" in node and ("cpu" in node["ImageURL"] or "nvidia" in node["ImageURL"]):
        current_hw = node["Text"]

    if "Value" in node:
        results.append({
            "hardware": current_hw,
            "sensor": node.get("Text"),
            "value": node.get("Value"),
            "min": node.get("Min"),
            "max": node.get("Max")
        })

    for child in node.get("Children", []):
        results.extend(flatten_sensors(child, current_hw))
    return results

def monitor_loop():
    print("🚀 啟動 Libre Hardware Monitor 自動監控守護程式...")
    while True:
        try:
            resp = requests.get(LHM_API_URL, timeout=2)
            data = resp.json()
            sensors = flatten_sensors(data)

            # 抓取 CPU 與 GPU 關鍵溫度
            for s in sensors:
                if s["sensor"] in ["CPU Package", "GPU Core"] and "°C" in s["value"]:
                    temp_val = float(s["value"].replace(" °C", "").replace(",", "."))
                    print(f"[{s['hardware']}] {s['sensor']}: {temp_val:.1f} °C (Max: {s['max']})")
                    
                    if temp_val >= TEMP_THRESHOLD:
                        print(f"⚠️ 警告！{s['hardware']} 溫度過高 ({temp_val}°C)，觸發警報！")
                        winsound.Beep(1200, 400) # 頻率 1200Hz，持續 400ms

        except requests.exceptions.RequestException as e:
            print(f"❌ 連線失敗，請確認 LHM Remote Web Server 已啟動: {e}")
        
        time.sleep(1.5)

if __name__ == "__main__":
    monitor_loop()

6. .NET (C#) LibreHardwareMonitorLib 深度二次開發實戰

如果你正在開發 Windows 原生桌面程式（WPF、WinForms、Avalonia、.NET MAUI 或 Windows 服務），你完全不需要透過 HTTP 繞路。直接引入官方提供的 LibreHardwareMonitorLib，能獲得最高效能、零延遲的記憶體原生呼叫！

6.1 安裝 NuGet 套件

dotnet add package LibreHardwareMonitorLib

6.2 深入理解 Visitor 模式架構

為什麼 LHM 要採用經典的 訪問者模式 (Visitor Pattern)？因為硬體拓撲結構非常複雜（Computer 包含多個 Hardware，Hardware 包含 SubHardware 與多個 Sensor）。如果每次讀取都要手動寫深層迴圈，代碼會非常混亂且缺乏彈性。透過 IVisitor，只要寫一個 Visitor 類別傳入 computer.Accept(visitor)，就能自動遍歷整顆硬體樹！

6.3 生產級高效能 C# 類別程式碼範例

以下是具備資源自動釋放 (IDisposable)、選擇性硬體開啟 (降低啟動耗時 90%) 的完整實作：

using System;
using System.Threading;
using System.Threading.Tasks;
using LibreHardwareMonitor.Hardware;

namespace HardcoreEngineer.Telemetry
{
    public sealed class HardwareMonitorService : IDisposable
    {
        private readonly Computer _computer;
        private readonly UpdateVisitor _visitor;
        private bool _disposed;

        public class UpdateVisitor : IVisitor
        {
            public void VisitComputer(IComputer computer) => computer.Traverse(this);
            public void VisitHardware(IHardware hardware)
            {
                hardware.Update(); // 向底層驅動發送即時採樣更新指令
                foreach (IHardware subHardware in hardware.SubHardware)
                    subHardware.Accept(this);
            }
            public void VisitSensor(ISensor sensor) { }
            public void VisitParameter(IParameter parameter) { }
        }

        public HardwareMonitorService()
        {
            _visitor = new UpdateVisitor();

            // 最佳化秘訣：只開啟業務所需的硬體！
            // 全開會導致探測所有 Storage、PCI 晶片，啟動耗時高達 2~3 秒
            _computer = new Computer
            {
                IsCpuEnabled = true,
                IsGpuEnabled = true,
                IsMemoryEnabled = true,
                IsMotherboardEnabled = false, // 若不需要主機板電壓，關閉可極速啟動
                IsControllerEnabled = false,
                IsNetworkEnabled = false,
                IsStorageEnabled = false
            };

            _computer.Open(); // 載入 WinRing0x64.sys 驅動並初始化把柄
        }

        /// 
        /// 採樣硬體遙測並印出數據
        /// 
        public void SampleTelemetry()
        {
            if (_disposed) throw new ObjectDisposedException(nameof(HardwareMonitorService));

            _computer.Accept(_visitor); // 執行訪問者更新

            foreach (IHardware hardware in _computer.Hardware)
            {
                Console.WriteLine($"\n🔹 硬體組件: {hardware.Name} [{hardware.HardwareType}]");
                foreach (ISensor sensor in hardware.Sensors)
                {
                    if (sensor.SensorType == SensorType.Temperature || sensor.SensorType == SensorType.Load)
                    {
                        Console.WriteLine($"   ├── 感測器: {sensor.Name,-24} | 類型: {sensor.SensorType,-12} | 當前值: {sensor.Value:F1}");
                    }
                }
            }
        }

        /// 
        /// 支援風扇 PWM 控制範例 (僅適用於具備 Control 類型的晶片)
        /// 
        public void SetFanSpeedPercentage(string fanName, float percent)
        {
            foreach (IHardware hardware in _computer.Hardware)
            {
                foreach (ISensor sensor in hardware.Sensors)
                {
                    if (sensor.SensorType == SensorType.Control && sensor.Name.Contains(fanName))
                    {
                        sensor.Control.SetSoftware(percent);
                        Console.WriteLine($"⚡ 已將風扇 [{sensor.Name}] 轉速鎖定為 {percent}%");
                        return;
                    }
                }
            }
        }

        public void Dispose()
        {
            if (!_disposed)
            {
                _computer.Close(); // 重要！務必關閉以正確卸載驅動與釋放核心把柄
                _disposed = true;
            }
        }
    }

    class Program
    {
        static void Main()
        {
            using var monitor = new HardwareMonitorService();
            for (int i = 0; i < 3; i++)
            {
                monitor.SampleTelemetry();
                Thread.Sleep(1000);
            }
        }
    }
}

7. WMI 整合與系統管理員 PowerShell 自動化告警

Windows Management Instrumentation (WMI) 是微軟標準的企業管理架構。Libre Hardware Monitor 支援將所有感測器數據即時廣播到 Windows 系統的 WMI 資料庫中，讓系統工程師使用 PowerShell 就能進行全自動巡檢！

7.1 啟用 WMI 廣播

在 Libre Hardware Monitor 視窗中，點擊選單 Options → WMI → 勾選 Enable WMI 即可。數據會直接注入到專屬的 root\LibreHardwareMonitor 命名空間中。

7.2 WMI 結構與 SensorType 完整對照表

在 root\LibreHardwareMonitor 中，有兩個核心 WMI 類別：

  • Hardware 類別：代表實體零件，具備 Identifier, Name, HardwareType 等欄位。
  • Sensor 類別：代表各項遙測指標，核心欄位包含：Identifier, Name, SensorType, Value, Min, Max, Index。
SensorType 列舉名稱 物理單位 典型應用情境
Voltage伏特 (V)CPU Vcore、DRAM 電壓、主機板 +12V / +5V 供電穩定度
Clock兆赫 (MHz)CPU 核心時脈、GPU 核心與顯存時脈
Temperature攝氏度 (°C)CPU Package、GPU Hotspot、NVMe SSD 複合溫度
Load百分比 (%)CPU 總使用率、GPU 3D 渲染負載、記憶體佔用率

7.3 PowerShell 實戰 1：一鍵硬體全景健檢清單

# 查詢所有溫度大於 50°C 的感測器
Get-CimInstance -Namespace "root\LibreHardwareMonitor" -ClassName Sensor | 
    Where-Object { $_.SensorType -eq "Temperature" -and $_.Value -gt 50 } | 
    Select-Object Name, @{Name="溫度 (°C)"; Expression={"$($_.Value) °C"}}, @{Name="峰值"; Expression={"$($_.Max) °C"}} | 
    Format-Table -AutoSize

7.4 PowerShell 實戰 2：超溫自動發送 Windows 桌面通知與事件日誌記錄

這段腳本可設定為 Windows 背景定期工作，當發現 CPU 溫度破表時，自動透過 PowerShell 觸發 Windows 10/11 桌面 Toast 通知，並寫入系統事件簿 (Event Log)：

# 定義警戒門檻
$MaxCpuTemp = 85.0
$Namespace = "root\LibreHardwareMonitor"

# 抓取 CPU 溫度
$CpuTempSensor = Get-CimInstance -Namespace $Namespace -ClassName Sensor | 
    Where-Object { $_.SensorType -eq "Temperature" -and $_.Name -like "*CPU Package*" } | 
    Select-Object -First 1

if ($CpuTempSensor -and $CpuTempSensor.Value -ge $MaxCpuTemp) {
    $CurrentTemp = $CpuTempSensor.Value
    $Msg = "⚠️ 警告：CPU Package 溫度已達到 $($CurrentTemp)°C，超過警戒線 $($MaxCpuTemp)°C！"
    Write-Warning $Msg

    # 1. 寫入 Windows 系統事件日誌 (Application Log)
    Write-EventLog -LogName Application -Source "HardwareWatchdog" -EntryType Warning -EventId 9001 -Message $Msg -ErrorAction SilentlyContinue

    # 2. 發送 Windows 10/11 桌面原生氣泡通知
    [reflection.assembly]::loadwithpartialname("System.Windows.Forms") | Out-Null
    $notify = New-Object System.Windows.Forms.NotifyIcon
    $notify.Icon = [System.Drawing.SystemIcons]::Warning
    $notify.Visible = $true
    $notify.ShowBalloonTip(5000, "硬體高溫警報！", $Msg, [System.Windows.Forms.ToolTipIcon]::Warning)
}

9. 實務避坑手冊與常見問題 FAQ

Q1: 為什麼打開軟體後看不到 CPU 溫度，或者數值全部顯示為 0？

原因：這 99% 是因為沒有以系統管理員身分執行。如第二章所述，存取 MSR 暫存器需要核心模式驅動權限。如果只是普通權限點開，Windows 會拒絕加載 WinRing0x64.sys，導致 CPU/主機板節點空白。請務必右鍵點選「以系統管理員身分執行」，或依照第四章設定工作排程器。

Q2: 遇到微軟「易受攻擊驅動程式封鎖清單 (Vulnerable Driver Blocklist)」或 Windows Defender 封鎖怎麼辦？

原因：微軟自 Windows 11 22H2 起啟用了內核驅動嚴格審查機制。早期版本的 Open Hardware Monitor 或極舊版 LHM 使用的舊版 WinRing0 驅動曾被黑客拿來進行權限提升，因而被列入微軟封鎖清單。

解法：

  • 確保使用 Libre Hardware Monitor 最新發布版本，新版已更新經過安全修補與受信任憑證簽署的內核驅動。
  • 若在特殊環境仍然受阻，可以在 Windows 安全性中檢查「核心隔離 (Core Isolation)」裡面的「易受攻擊的驅動程式封鎖清單」，並為 LHM 執行目錄加入白名單排除。

Q3: 同時開啟 HWiNFO64、ASUS Armoury Crate 或 Corsair iCUE 時，風扇轉速狂跳或感測器數值卡死？

原因：LPC 總線競爭與互斥鎖 (Mutex) 衝突。 主機板上的 Super I/O 晶片只有一個 I/O 埠定址管道。當多個監控軟體在同一毫秒發送 IN/OUT 指令存取同一個暫存器時，就會引發競態條件 (Race Condition)，導致讀回 0xFF 異常值。

最佳實踐：在各監控軟體中啟用「全域硬體監控互斥鎖 (Global Hardware Monitor Mutex)」，或者避免同時執行兩個以上會高頻輪詢 Super I/O 的軟體。

Q4: Remote Web Server 只能在本機存取，如何允許區網 (LAN) 其他電腦或手機連線？

原因：Windows Defender 防火牆預設會阻擋外部設備存取 8085 連接埠。

解法：在 Windows 系統管理員 PowerShell 中執行一行指令開放防火牆入站規則：

New-NetFirewallRule -DisplayName "LibreHardwareMonitor WebServer" -Direction Inbound -LocalPort 8085 -Protocol TCP -Action Allow

Q5: 如何在無人登入的 Windows Server 伺服器上當作 Windows Service 常駐運行？

原因：Windows Service 運行在 Session 0 隔離環境中，某些依賴使用者桌面 session 的驅動通訊在 Session 0 可能受到安全限制。

解法：建議使用本指南第四章推薦的工作排程器 (Task Scheduler)，觸發條件設定為「啟動電腦時 (At startup)」，並指定以 SYSTEM 帳戶或具備本機管理員權限的服務帳戶運行，勾選「不論使用者登入與否均執行」。

10. 結語與延伸架構思維

Libre Hardware Monitor 絕不僅僅是一款擺在桌面看溫度的視覺工具，它更是一套低延遲、開源、模組化的系統遙測底層引擎。

無論你是要：

  • 為自己的機房伺服器建立 Grafana + Prometheus 硬體健康度監控；
  • 為自組水冷遊戲主機開發專屬副螢幕儀表板；
  • 在 C# 商業專案中即時監測工控機或渲染農場的負載與風扇保護；
  • 抑或是寫一段幾十行的 Python / PowerShell 腳本打造超溫自動告警與保護降載；

Libre Hardware Monitor 都憑藉其豐富的介面（HTTP JSON API、.NET 函式庫、WMI 廣播）為工程師提供了極大的自由度與無限可能。掌握它的底層原理與串接方式，將讓你的系統架構在穩定性與可觀測性上更上一層樓！
