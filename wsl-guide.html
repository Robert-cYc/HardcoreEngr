Windows Subsystem for Linux (WSL) 完全攻略：在 Windows 上享受原生 Linux 開發體驗

2026-10-06 · 18 分鐘閱讀
WSL Linux Windows Ubuntu 開發工具 教學
🎯 重點摘要：
  ① 什麼是 WSL：微軟推出的工具，讓開發者在 Windows 上直接執行原生 Linux 環境，免除傳統虛擬機的龐大開銷。
  ② WSL 2 的架構：採用輕量級 Hyper-V 虛擬機與真正的 Linux 核心，提供 100% 系統呼叫相容性與極速檔案系統。
  ③ 無縫整合：透過 VS Code Remote 擴充套件，在 Windows 的圖形介面下撰寫程式，執行環境卻完全在 Linux 中。
  ④ 檔案互通：Windows 可透過 \\wsl$ 直接存取 Linux 檔案；Linux 可透過 /mnt/c 存取 Windows C 槽。

為什麼你需要 WSL？

在過去，Windows 開發者想要在本地端模擬 Linux 環境，通常有幾個選擇：裝雙系統（麻煩）、用 VirtualBox 等虛擬機（極吃資源且笨重）、或者使用 Cygwin/Git Bash（相容性差且速度慢）。

Windows Subsystem for Linux (WSL) 徹底改變了這個局面。它不僅輕量、啟動極快（僅需幾秒鐘），更支援真正的 Linux 核心，讓所有 Docker、Node.js、Python 等工具都能以原生效能運行。微軟甚至在其中加入了對圖形化介面 (GUI) 應用程式的支援，讓你在 Windows 桌面直接開啟 Linux 應用軟體。

WSL 1 vs WSL 2

WSL 經歷過一次重大的架構改版，強烈建議使用 WSL 2：

功能WSL 1WSL 2 (推薦)
架構原理將 Linux 系統呼叫即時翻譯成 Windows NT 呼叫在輕量化 Hyper-V 虛擬機內執行完整的 Linux 核心
啟動速度極快極快
檔案系統效能跨系統存取稍快，但 Linux 內部操作慢Linux 內部操作極速，跨系統存取較慢
相容性部分依賴底層特性的軟體無法執行 (如 Docker)100% 系統呼叫相容，支援所有 Linux 軟體與 Docker

目前的預設安裝皆為 WSL 2。

一行指令完成安裝

在 Windows 10 (版號 2004 以上) 或 Windows 11 中，安裝 WSL 已經簡化到只需要打開具有管理員權限的 PowerShell 或 Windows Terminal，並輸入：

wsl --install

這個指令會自動：

  1. 啟用必要的 Windows 虛擬機器平台功能。
  2. 下載並安裝最新的 Linux 核心。
  3. 下載並安裝預設的發行版（通常是 Ubuntu）。

安裝完成後，重新啟動電腦。重開機後，一個 Ubuntu 的終端機視窗會自動彈出，要求你設定一組 UNIX 帳號與密碼（這組帳號密碼與 Windows 系統無關）。

管理你的 Linux 發行版

指令作用
wsl -l -v列出所有已安裝的 Linux 發行版及其 WSL 版本 (1 或是 2)。
wsl --list --online列出官方線上商店可供安裝的其他發行版 (如 Debian, Kali 等)。
wsl --install -d <Distro>安裝特定的發行版，例如：wsl --install -d Debian。
wsl --set-default-version 2將預設的新發行版安裝為 WSL 2 版本。
wsl --set-version <Distro> 2將舊版的 WSL 1 發行版升級為 WSL 2 (例如：wsl --set-version Ubuntu 2)。
wsl --shutdown立即關閉所有正在運行的 WSL 虛擬機 (釋放記憶體)。

開發神器：VS Code 完美整合

WSL 真正的威力在於與 Visual Studio Code 的無縫整合。你不需在終端機裡用 vim 寫程式，可以享受現代編輯器的所有好處。

  1. 在 Windows 上安裝好 VS Code。
  2. 在 VS Code 的擴充功能市集中，搜尋並安裝 WSL (由 Microsoft 提供) 套件。
  3. 打開你的 WSL 終端機（例如 Ubuntu），建立一個專案資料夾並進入。
  4. 輸入神奇的指令：code .

此時，Windows 的 VS Code 會啟動，但左下角會顯示連線到「WSL: Ubuntu」。在這個模式下：

  • 檔案： 你在編輯的是 Linux 檔案系統內的檔案。
  • 終端機： VS Code 內建的終端機會直接開啟 bash/zsh，而不是 PowerShell。
  • 擴充套件： Node.js、Python 等語言擴充套件會安裝在 Linux 端，利用 Linux 原生的編譯器來提供自動完成與除錯。

檔案系統的互通有無

WSL 讓 Windows 和 Linux 兩個世界的檔案可以互相存取：

1. 從 Windows 存取 Linux 檔案

打開 Windows 檔案總管，在網址列輸入：

\\wsl$

或者在較新的 Windows 11 中，左側導覽列會有一個「Linux」的企鵝圖示。你可以直接把圖片拖進去，或是用 Windows 的工具編輯裡面的文件。

2. 從 Linux 存取 Windows 檔案

Windows 的 C 槽會自動掛載在 Linux 的 /mnt/c。例如要切換到 Windows 的桌面：

cd /mnt/c/Users/你的帳號名稱/Desktop
⚠️ 效能警告：在 WSL 2 中，跨檔案系統存取（例如在 Linux 內操作 Windows 的 /mnt/c 內的檔案）速度非常慢。因此，請務必把你的開發專案放在 Linux 原生檔案系統中 (如 ~ 家目錄)，而不是 Windows C 槽！

Docker 與 WSL 2：天作之合

過去在 Windows 上跑 Docker 要依賴肥重的 Hyper-V 虛擬機，現在 Docker Desktop 原生支援基於 WSL 2 的引擎：

  1. 安裝 Docker Desktop for Windows。
  2. 在設定中勾選 "Use the WSL 2 based engine"。
  3. 到 Settings > Resources > WSL integration，勾選你要整合的發行版（如 Ubuntu）。

設定好後，你在 Windows 上的 docker 指令與在 WSL Ubuntu 裡的 docker 指令，操作的是同一個守護進程 (Daemon) 與容器，效能完全比照原生 Linux，體驗極佳。

進階：設定資源限制 (.wslconfig)

WSL 2 的虛擬機會動態吃掉主機記憶體。如果不加以限制，有時會吃光所有的 RAM。你可以在 Windows 的使用者目錄（C:\Users\<你的帳號>\）下建立一個名為 .wslconfig 的檔案來限制它：

# C:\Users\你的帳號\.wslconfig
[wsl2]
memory=8GB        # 限制 WSL 最多只能使用 8GB 的 RAM
processors=4      # 限制只使用 4 個 CPU 核心
swap=2GB          # 設定 2GB 的 Swap 空間

存檔後，在 PowerShell 執行 wsl --shutdown，下次啟動 WSL 時設定就會生效。

總結

WSL 2 是一項劃時代的技術，它讓前端工程師能無痛使用各種 Node.js 原生編譯套件、讓後端工程師能使用最接近正式伺服器的環境開發、讓資料科學家能輕鬆調用 GPU。如果你是 Windows 使用者，請立刻安裝 WSL，它絕對是你開發路上的最強助力。
