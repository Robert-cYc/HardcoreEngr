PyInstaller 完全操作指南：安裝、--onefile 與 --onedir 核心指令詳解、資源打包與除錯避坑手冊

2026-10-13 · 18 分鐘閱讀 · 分類：開發工具與 Python
PyInstaller Python 打包 exe 製作 CLI 指令 開發工具 教學
TL;DR 速覽：
• 什麼是 PyInstaller？ 一款將 Python 腳本連同 Python 直譯器環境、動態依賴庫（DLL/so/dylib）打包為獨立可執行檔（Windows .exe、macOS App、Linux binary）的打包工具，目標電腦無需安裝 Python 即可直接執行。
• 核心旗標核心差異：
  - --onefile (-F)：打包為單一獨立執行檔。方便分發，但啟動時會先解壓縮到暫存目錄，啟動略慢。
  - --onedir (-D，預設)：打包為包含執行檔與依賴檔的資料夾。啟動極快、方便替換設定與除錯，分發時建議壓縮為 zip。
• 絕不能漏的關鍵細節： 打包外部靜態資源（圖片、設定檔）時，需搭配 --add-data，並在 Python 程式碼中透過 sys._MEIPASS 動態定位暫存路徑。
• 最佳實踐： 強烈建議在乾淨的虛擬環境 (venv) 中打包，否則會將全域所有龐大套件一同捲入，造成 exe 肥大至數百 MB！

一、什麼是 PyInstaller？底層運作原理剖析

在 Python 開發中，我們常面臨交付軟體的難題：一般使用者電腦通常沒有安裝 Python，也沒有設定好 pip 依賴，甚至可能會遇到版本衝突。PyInstaller 正是為了解決這個痛點而生的業界標準解決方案。

PyInstaller 的工作原理並非「將 Python 程式碼編譯成 C++ 或機器碼」，而是執行以下自動化流程：

  1. 依賴靜態分析： 深度解析你的入口腳本（如 main.py），遍歷所有 import 語句，構建模組依賴樹狀圖。
  2. 環境收集： 從目前使用的 Python 環境中提取對應版本的 Python 直譯器核心動態庫（如 python311.dll）、標準庫二進位檔（.pyd）及第三方依賴包。
  3. 內建 Bootloader： 加入編譯好的引導啟動程式（Bootloader）。當使用者點擊產生的 .exe 時，Bootloader 會建立獨立的 Python 執行期環境並啟動腳本。

二、PyInstaller 安裝與環境準備

1. 標準安裝 (pip)

在終端機（PowerShell、CMD 或 bash）中直接使用 pip 安裝：

# 安裝最新穩定版本
pip install pyinstaller

# 驗證安裝成功與查看版本
pyinstaller --version

2. 升級至最新版或開發版

若你的 Python 是剛發布的新版本（例如 Python 3.12+ / 3.13），建議更新至官方開發分支以避免語法樹解析相容性問題：

# 升級現有版本
pip install --upgrade pyinstaller

# 安裝 GitHub 最新開發分支
pip install https://github.com/pyinstaller/pyinstaller/tarball/develop

3. 核心建議：務必在獨立虛擬環境中打包！

許多初學者抱怨「只有幾行代碼的腳本打包出來竟然有 300MB！」，其根本原因就是直接在全域 Python 環境執行打包。PyInstaller 會嘗試收集所有被間接探測到的套件（如 pandas、torch、matplotlib 等）。

# 1. 建立乾淨的虛擬環境
python -m venv .venv

# 2. 啟動虛擬環境
# Windows PowerShell:
.\.venv\Scripts\Activate.ps1
# macOS / Linux:
source .venv/bin/activate

# 3. 僅安裝該專案真正需要的套件與 PyInstaller
pip install requests pyinstaller

三、核心指令與參數詳解速查手冊

PyInstaller 提供了非常豐富的 CLI 參數，掌握以下核心參數即可涵蓋 95% 以上的日常打包情境：

參數選項 簡寫 功能說明 適用情境
--onefile -F 打包成單一獨立可執行檔 分發給終端客戶、免安裝獨立工具
--onedir -D 打包為一個目錄（包含 exe 與眾多依賴）（預設選項） 大型專案、頻繁啟動程式、除錯測試
--windowed / --noconsole -w 無主控台視窗，不彈出黑色命令提示字元黑框 Tkinter、PyQt、wxPython 等桌面 GUI 程式
--console / --nowindowed -c 顯示主控台視窗（預設選項） CLI 命令列工具、排查報錯與印出日誌
--icon=<PATH> -i 設定產物圖示（Windows .ico，macOS .icns） 打造具備企業與品牌識別度的執行檔
--name=<NAME> -n 指定輸出的 exe / 目錄自訂名稱 修改檔名，預設為入口腳本的主檔名
--add-data <SRC;DEST> - 將外部檔案/資料夾一同打包（Windows 用 ;，Unix 用 :） 打包圖片、JSON 設定檔、HTML/CSS 靜態模板
--add-binary <SRC;DEST> - 將額外的二進位函式庫（DLL、.so）打包進去 調用自製 C/C++ 共享庫或驅動
--hidden-import=<PKG> - 強制標記隱藏導入模組（手動補齊） 動態 import、__import__、Plugin 架構
--exclude-module=<PKG> - 明確排除特定無用套件 極致減肥，剔除未使用的重量級模組
--clean - 打包前自動清理舊快取與暫存目錄 更換設定或程式碼大幅變更後的乾淨建置
--distpath <DIR> - 自訂最終執行檔輸出目標資料夾（預設為 dist/） 自動化 CI/CD 工作流發布目錄配置

四、--onefile vs. --onedir 核心差異與選型對策

📦 --onefile (單一執行檔模式)

打包結果： 僅產出一個獨立的 myapp.exe。

執行機制： 每次點擊執行時，Bootloader 會在作業系統的暫存區（Windows 上的 %TEMP%/_MEIxxxxxx）創建一個臨時解壓資料夾，將所有依賴解壓後才開始運行 Python 直譯器，程式結束後自動刪除該目錄。

優勢： 單一檔案，極簡乾淨，分發時使用者只需下載一個檔案。

劣勢： 每次啟動有解壓開銷（冷啟動慢）；若打包外部檔案需特別處理暫存路徑。

📁 --onedir (資料夾目錄模式 - 預設)

打包結果： 產出一個包含 myapp.exe 與數十個依賴檔案、DLL 的 dist/myapp/ 資料夾。

執行機制： exe 直接在當前資料夾讀取周圍的依賴函式庫，無需任何解壓過程。

優勢： 啟動秒開、極速響應；排查缺失 DLL 非常直觀；若需更新圖片或設定檔，直接手動替換即可，無需重新打包整份專案。

劣勢： 檔案分散，分發時必須手動壓縮成 zip 包或搭配 Inno Setup 製作安裝包。

五、完整實戰操作教學：從零打包一個真實應用

我們以一個包含設定檔 config.json 與圖片 logo.png 的真實腳本為例，完整演示標準化打包工作流。

1. 專案目錄結構

my_project/
├── assets/
│   └── logo.png
├── config.json
└── main.py

2. 關鍵程式碼：處理打包前後資源路徑 (sys._MEIPASS 萬用模板)

在 --onefile 打包後，程式執行時所有資源都會被解壓到臨時目錄 sys._MEIPASS 中。如果直接用 open('config.json')，會導致找不到檔案的 FileNotFoundError 崩潰。請務必在代碼中引入以下萬用路徑解析函式：

# main.py
import sys
import os
import json

def get_resource_path(relative_path: str) -> str:
    """取得資源的絕對路徑，兼容開發環境與 PyInstaller 打包環境"""
    try:
        # PyInstaller 打包後會創建 _MEIPASS 暫存路徑
        base_path = sys._MEIPASS
    except AttributeError:
        # 未打包的標準本地開發環境
        base_path = os.path.abspath(".")
    return os.path.join(base_path, relative_path)

def main():
    config_file = get_resource_path("config.json")
    print(f"正在讀取設定檔路徑: {config_file}")
    
    with open(config_file, "r", encoding="utf-8") as f:
        config = json.load(f)
    print(f"應用程式名稱: {config.get('app_name', '未命名')}")

    logo_file = get_resource_path(os.path.join("assets", "logo.png"))
    print(f"靜態資源存在檢查: {os.path.exists(logo_file)}")

if __name__ == "__main__":
    main()

3. 執行打包指令

將 main.py、外部檔案 config.json 及 assets 資料夾整合打包為單一桌面執行檔：

# Windows 環境命令（注意分號 ; 區隔來源與目標路徑）
pyinstaller --onefile \
  --name="MyAwesomeApp" \
  --add-data="config.json;." \
  --add-data="assets/logo.png;assets" \
  --clean \
  main.py

# macOS / Linux 環境命令（注意冒號 : 區隔）
pyinstaller --onefile \
  --name="MyAwesomeApp" \
  --add-data="config.json:." \
  --add-data="assets/logo.png:assets" \
  --clean \
  main.py

4. 打包產物說明

  • dist/：存放最終生成的可執行檔（交付給使用者的核心成果）。
  • build/：編譯過程中的暫存分析檔與日誌，確認產物無誤後可隨時手動刪除。
  • MyAwesomeApp.spec：PyInstaller 自動產生的建置規格檔（Spec 檔），非常適合納入 Git 版本控制，用於後續自動化重現打包。

六、進階技巧：使用 .spec 規格檔優雅管理複雜配置

當參數越來越多時，在終端機輸入長串 CLI 命令極易出錯且難以維護。透過直接編輯 .spec 檔案，可以如同寫 Python 代碼一般精細控制打包行為：

# -*- mode: python ; coding: utf-8 -*-
# MyAwesomeApp.spec

block_cipher = None

a = Analysis(
    ['main.py'],
    pathex=[],
    binaries=[],
    # 集中管理所有外部打包資源 [(來源路徑, 目標目錄)]
    datas=[
        ('config.json', '.'),
        ('assets/logo.png', 'assets'),
    ],
    # 手動補齊動態隱藏套件
    hiddenimports=['requests', 'charset_normalizer'],
    hookspath=[],
    hooksconfig={},
    runtime_hooks=[],
    # 明確排除巨大無用庫，大幅瘦身
    excludes=['tkinter', 'matplotlib', 'scipy'],
    win_no_prefer_redirects=False,
    win_private_assemblies=False,
    cipher=block_cipher,
    noarchive=False,
)

pyz = PYZ(a.pure, a.zipped_data, cipher=block_cipher)

exe = EXE(
    pyz,
    a.scripts,
    a.binaries,
    a.zipfiles,
    a.datas,
    [],
    name='MyAwesomeApp',
    debug=False,
    bootloader_ignore_signals=False,
    strip=False,
    upx=True,           # 啟用 UPX 執行檔壓縮（需安裝 UPX）
    console=True,       # 是否顯示 Console
    icon='app.ico',     # 自訂圖示
)

修改好規格檔後，日後只需一行簡潔命令即可快速建置：

pyinstaller MyAwesomeApp.spec

七、高頻踩坑與除錯避坑指南 (Troubleshooting)

💥 痛點 1：雙擊 exe 瞬間閃退，看不到錯誤訊息

診斷： 如果使用了 --windowed 或 -w，一旦程式出錯崩潰，由於沒有主控台，視窗會瞬間關閉消失。

解法： 先拿掉 -w 重新打包成具備 Console 的模式，並在命令提示字元 (CMD/PowerShell) 中手動敲入 .\dist\app.exe 執行，即可完整看到 Traceback 錯誤堆疊。

📉 痛點 2：打包出的 exe 體積高達 200MB~500MB

診斷： 使用全域 Python 環境，未加思索地將包含 Anaconda/全局庫的所有關聯模組整包打包。

解法： 1. 強烈建立乾淨的 venv 虛擬環境；2. 在 spec 檔或命令中使用 --exclude-module 排除大型科學運算庫；3. 安裝 UPX 壓縮工具（在 PATH 中放入 upx.exe）。

🔍 痛點 3：ModuleNotFoundError: No module named 'xxx'

診斷： 程式碼中使用了反射、importlib.import_module() 或字串動態加載，PyInstaller 靜態語法樹無法自動探測。

解法： 在命令列加上 --hidden-import="xxx" 或在 spec 檔的 hiddenimports 清單中明確補齊。

🛡️ 痛點 4：Windows Defender / 防毒軟體報毒或被攔截

診斷： PyInstaller 的預編譯 Bootloader 經常被各路木馬病毒拿去封裝惡意腳本，導致通用特徵碼被部分防毒軟體無差別標記為「潛在威脅 (Trojan/False Positive)」。

解法： 1. 在自己電腦中從原始碼編譯 PyInstaller Bootloader；2. 購買代碼簽名證書（Code Signing Certificate）進行數位簽名；3. 提交誤報樣本給微軟安全中心審核。

八、總結與最佳實踐檢核清單

將 Python 專案成功交付給使用者，是從開發邁向生產的關鍵一步。在進行任何正式打包前，請對照以下最佳實踐檢核表：

  • ✅ 是否已在乾淨的虛擬環境 (venv) 中測試過腳本功能？
  • ✅ 所有讀取外部靜態資源的路徑，是否都使用了 sys._MEIPASS 兼容函式處理？
  • ✅ 初次除錯時，是否保留了 --console 視窗以便即時排查錯誤？
  • ✅ 是否保存了 .spec 規格檔以便在 CI/CD 中實現穩定重現的自動化打包？
  • ✅ 若需要跨平台運行（例如同時產出 Windows 與 Linux 版本），是否在對應的作業系統環境（或 Docker 容器）中執行打包？（注意：PyInstaller 無法交叉編譯）
