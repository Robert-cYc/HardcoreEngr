作業系統 (OS) 底層架構全解析：Windows, macOS, Linux 與 Android

2026-10-03 · 18 分鐘閱讀
OS 作業系統 Windows macOS Linux Android 架構

在我們每天敲打鍵盤、滑動手機螢幕的背後，作業系統 (Operating System, OS) 扮演著無名英雄的角色。它就像是一個龐大帝國的交通警察與管家，負責在「硬體 (CPU、記憶體、硬碟)」與「軟體 (瀏覽器、遊戲、IDE)」之間進行精準的資源調度。

雖然我們每天都在用，但你真的了解它們底層的運作邏輯嗎？為什麼 Windows 能相容三十年前的軟體？為什麼 macOS 的體驗如此絲滑？為什麼全世界的伺服器都跑 Linux？Android 又是如何讓 Java/Kotlin 跑在手機硬體上？

今天，我們就從硬核工程師的視角，直接剖析 Windows、macOS、Linux 與 Android 的核心架構 (Kernel) 與設計哲學。

1. Windows：向後相容的企業巨獸 (Windows NT 核心)

Windows 是目前桌面端市佔率絕對的霸主。它最常被工程師詬病「底層複雜、登錄檔 (Registry) 是一場災難」，但這其實是微軟為了一個偉大目標所付出的代價：絕對的向後相容性 (Backward Compatibility)。

核心架構：Windows NT (New Technology)

現代的 Windows (從 XP、Win7 到 Win11) 都是基於 NT 核心。它採用的是一種混合核心 (Hybrid Kernel) 設計，結合了宏核心 (Monolithic) 的效能與微核心 (Microkernel) 的模組化。

  • 登錄檔 (Registry)：這是一個巨大的階層式資料庫，用來儲存系統與所有軟體的設定。好處是集中管理，壞處是一旦這個資料庫龐大且混亂，系統就會變得極度緩慢。
  • DirectX：微軟自家的多媒體與遊戲 API。這是 Windows 成為全球唯一「電競 OS」的護城河，因為它能極度高效地直接調用 GPU 資源。
  • WSL (Windows Subsystem for Linux)：為了挽回流失到 Mac 的開發者，微軟在 Windows 中透過 Hyper-V 技術，直接內建了一個真正的 Linux 核心 (WSL2)。這讓 Windows 變成了全端開發者的超級兵器。

2. macOS：優雅的混血貴族 (XNU / Darwin)

macOS (前身為 Mac OS X) 的底層其實與 iPhone 的 iOS 同源，它們都有著純正的 UNIX 血統。這也是為什麼開發者特別愛用 Mac，因為你打開終端機 (Terminal)，所有在 Linux 伺服器上的指令，在 Mac 幾乎都能無縫運行。

核心架構：XNU (Mach + BSD)

macOS 的核心稱為 XNU (X is Not Unix)，這是一個非常有趣的混合體：

  • Mach 核心：負責最底層的任務排程、記憶體管理與處理器間通訊 (IPC)。
  • BSD 系統 (基於 FreeBSD)：覆蓋在 Mach 之上，提供 POSIX 標準的 API、檔案系統、網路堆疊以及 UNIX 權限模型。

軟硬體一體化的優勢：不同於 Windows 要適配千萬種硬體，Apple 完全控制了從晶片 (Apple Silicon M系列) 到作業系統的所有細節。這種封閉生態讓 macOS 能做到極致的記憶體管理與功耗控制，這也是為什麼 MacBook 的續航力能輾壓同級對手。

3. Linux：開源世界的基石 (Monolithic Kernel)

Linux 不是一個完整的作業系統，它嚴格來說只是一個 Kernel (核心)。當你把 Linux Kernel 加上 GNU 工具鏈、桌面環境 (如 GNOME) 與套件管理員，才會變成我們熟知的 Ubuntu、Debian 或 CentOS 等發行版 (Distro)。

核心架構：宏核心 (Monolithic Kernel)

Linux 採用的是傳統的宏核心架構。也就是說，所有的驅動程式、檔案系統、網路堆疊，全部都跟核心跑在同一個記憶體空間 (Kernel Space)。

  • 極致效能：因為所有東西都在同一個空間，不需要頻繁的 User Space 與 Kernel Space 之間的 Context Switch，所以 I/O 效能極高。這讓 Linux 統治了全球 90% 以上的伺服器、超級電腦與雲端基礎設施。
  • 一切皆檔案 (Everything is a file)：這是 UNIX/Linux 最經典的設計哲學。你的硬碟、鍵盤、網路 Socket，在作業系統眼裡全都是「檔案」。這讓腳本自動化與資料導流 (Piping) 變得不可思議的簡單。
  • 高度模組化：雖然是宏核心，但 Linux 支援動態加載模組 (Loadable Kernel Modules, LKM)，你可以在不重開機的情況下，隨時載入或卸載驅動程式。

4. Android：披著 Linux 外皮的行動霸主

Android 的最底層其實就是 Linux Kernel，但它在上面疊加了無數層的魔改，讓它成為適合觸控、電池供電與行動裝置的系統。

核心架構：Linux Kernel + HAL + ART

  • Linux Kernel：負責最基礎的硬體溝通、記憶體分配、電源管理 (如 Android 專屬的 Wakelock 機制，防止手機在背景完全睡死)。
  • HAL (硬體抽象層)：因為 Android 手機硬體百百種 (高通、聯發科、三星)，Google 設計了 HAL。硬體廠商只要把自己的驅動包裝成 HAL 規定的標準介面，上層的 Android 系統就能直接調用，解決了嚴重的硬體碎片化問題。
  • ART (Android Runtime)：你寫的 Android App 通常是 Java 或 Kotlin，這些程式碼會被編譯成 Bytecode，然後由 ART 虛擬機來執行。ART 採用了 AOT (Ahead-of-Time) 編譯，在 App 安裝或系統閒置時，提前把代碼編譯成機器碼 (Machine Code)，大幅提升了 App 的啟動速度與運行效能。

結語：每個 OS 都在其領域閃耀

作為一名工程師，我們不該陷入「哪套 OS 最好」的無謂爭論。

Windows 是相容性與企業辦公的王者；macOS 是 UNIX 體驗與硬體效能完美結合的開發利器；Linux 則是雲端基礎設施的絕對基石；而 Android 則用極具彈性的架構，征服了全球數十億的行動裝置。

了解它們底層的設計哲學，有助於我們在開發軟體時，寫出更符合系統特性、效能更優越的程式碼。Talk is cheap, 去裝個虛擬機把這四套都玩一遍吧！
