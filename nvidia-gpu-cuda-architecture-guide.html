1. GPU vs. CPU 的第一性原理架構分歧

要透徹理解 GPU，必須從現代積體電路設計的「第一性原理」（First Principles）出發。現代矽片（Silicon Die）的物理面積與電晶體預算（Transistor Budget）是嚴格受限的。在相同的晶片面積與功耗限制（TDP）下，CPU 與 GPU 選擇了兩種截然相反的微架構哲學：

🖥️ CPU：延遲導向 (Latency-Optimized) 單核極致
  • 設計目標：最小化單一執行緒從發射到完成的絕對時間延遲（Latency）。
  • 晶片面積分配：超過 60%~70% 的矽片面積被巨大的一級/二級/三級快取（L1/L2/L3 Cache）以及複雜的控制邏輯（Control Logic）佔據。
  • 硬體技術：深層指令管線（14~20+ 階）、激進的亂序執行（Out-of-Order Execution, OOOE）、分支預測器（Branch Predictors）與推測執行（Speculative Execution）。
  • 適用場景：高度依賴控制流程、具有嚴格先後順序相依性的序列演算法（Sequential Code）。
⚡ GPU：吞吐量導向 (Throughput-Optimized) 海量並行
  • 設計目標：最大化單位時間內完成的總計算任務量（Throughput）。
  • 晶片面積分配：超過 80% 的矽片面積直接劃給算術邏輯單元（ALU Array / CUDA Cores / Tensor Cores），控制邏輯極度簡化。
  • 硬體技術：單指令多執行緒（SIMT）、大量執行緒上下文常駐暫存器、以硬體極速執行緒切換掩蓋長存取延遲（Latency Hiding）。
  • 適用場景：資料並行（Data-Parallel）、計算密集型任務（矩陣乘法、卷積、光線求交、物理模擬）。

1.1 Flynn 分類法與 SIMT vs. SIMD 的本質突破

在經典的 Flynn 計算機架構分類中，CPU 向量指令集（如 x86 AVX-512、ARM Neon）屬於 SIMD（Single Instruction, Multiple Data）：單一指令操作一個寬向量暫存器（如 512-bit 暫存器容納 16 個 32-bit 浮點數）。若程式碼中出現 if-else 分支，程式設計師必須手動撰寫掩碼指令（Blend/Mask）。

NVIDIA 發明的 SIMT（Single Instruction, Multiple Threads） 則是架構上的巨大飛躍：

  • 編程抽象獨立：在軟體層面，開發者撰寫純粹的純量程式碼（Scalar Thread），每個執行緒擁有自己獨立的暫存器、程式計數器（PC）與呼叫堆疊。
  • 硬體分組鎖步執行：硬體排程器將 32 個邏輯執行緒組裝為一個 Warp（執行緒束），由一個指令單元同步向 32 個 CUDA Core 廣播同一條指令。
  • 分支分歧硬體接管：當同一個 Warp 內的執行緒走向不同分支時，SIMT 硬體自動透過執行緒活躍遮罩（Active Mask）進行時間分片序列化執行，開發者無需在組譯層級手動拼裝向量暫存器。

1.2 Amdahl's Law 與異構計算邊界

在異構計算（Heterogeneous Computing）體系中，整體系統的加速比受到阿姆達爾定律（Amdahl's Law）的硬性制約：

$$S_{\text{latency}} = \frac{1}{(1 - p) + \frac{p}{s}}$$

其中 $p$ 為可高度並行化的程式比例，$s$ 為 GPU 的硬體加速倍數。即使 GPU 能將並行部分加速 10,000 倍（$s \to \infty$），若程式中有 5% 的代碼必須在 CPU 上單執行緒序列執行（$p = 0.95$），整體系統的最大理論加速比永遠無法超過 $1 / 0.05 = 20$ 倍。這就是為何現代 AI 架構（如 FlashAttention、CUDA Graph）極度強調「算子融合（Kernel Fusion）」與「消滅 Host-Device 交互開銷」。

2.1 SM (Streaming Multiprocessor)：GPU 運算的心臟

如果說 GPU 是航空母艦，那麼 SM（串流多處理器） 就是艦載戰機機庫與發射甲板。所有 CUDA Kernel 最終都被分派至各個 SM 內部執行。以現代 Hopper/Blackwell 架構為例，單個 SM 內部通常在邏輯上被劃分為 4 個完全對稱的子分區（SMSP, SM Sub-Partition）：

  • FP32 CUDA Cores32 個 (單精確度浮點)

  • SFU (Special Function)4 個 (倒數、三角、指數)

2.2 Warp Scheduler 與零開銷上下文切換 (Zero-Overhead Context Switching)

在傳統 CPU 中，執行緒上下文切換（Context Switch）代價極高（需幾百至上千個 CPU Clock Cycles），因為作業系統核心必須將暫存器內容備份至 RAM/L1 Cache，並重新載入另一個執行緒的狀態。

GPU 的運作模式完全顛覆了這一點：「零開銷上下文切換」。

每個 SM 內建 256KB 的龐大暫存器檔案（SRAM）。當一個 Thread Block 被分派到 SM 時，硬體會直接為該 Block 內的所有執行緒在實體暫存器檔案中就地分配（In-Place Allocate）專屬暫存器。這意味著：所有常駐在 SM 上的 Active Warps，其暫存器狀態永遠停留在硬體矽片上，不需要任何內存換出（Spill）。

Warp Scheduler 每個時脈週期只需執行一項極其簡單的檢查：Scoreboarding（記分板機制）。如果 Warp A 正在等待一條耗時 300 萬個週期的 DRAM 讀取指令返回，記分板將 Warp A 標記為 Not Ready；排程器在下一個週期直接將指令指針切換到已就緒的 Warp B。切換時間為 0 個 Clock Cycle！這就是 GPU 能夠透過海量執行緒隱匿超長記憶體延遲的根本原因。

3.1 Shared Memory 的 32-Bank 衝突機制 (Bank Conflicts)

Shared Memory 雖然位於晶片內部 SRAM、具備極高頻寬，但它的實體結構被劃分為 32 個獨立的儲存區塊（Banks），每個 Bank 寬度為 4 Bytes（32-bit）。連續的 32-bit 字依序輪流映射至不同的 Bank：

$$\text{Bank Index} = (\frac{\text{Byte Address}}{4}) \pmod{32}$$

當一個 Warp（32 個執行緒）同時發起對 Shared Memory 的存取時：

  • 無衝突理想狀況 (Conflict-Free)：32 個執行緒分別存取 32 個互不相同的 Banks，或者所有執行緒存取同一個 Bank 內的同一個位址（觸發硬體廣播 Multicast/Broadcast），此時只需要 1 個記憶體週期即可完成！
  • Bank 衝突 (Bank Conflict)：若多個執行緒存取同一個 Bank 內的不同位址，硬體無法並行讀取，必須將請求序列化（Serialized）。若發生 2-way 衝突，延遲翻倍；若發生最慘烈的 32-way 衝突，該條存取指令需要 32 個週期串列執行，共享記憶體頻寬直接暴跌 97%！
// 典型 32-Bank 衝突範例：跨步存取 (Stride Access)
__shared__ float s_data[32][32];

// 執行緒 tid 存取 column: s_data[tid][0]
// 由於每列有 32 個 float (128 bytes)，s_data[0][0], s_data[1][0]... 的 Bank Index 完全相同！
// 這將導致最嚴重的 32-Way Bank Conflict！
float val = s_data[threadIdx.x][0]; 

// 【硬核避坑解決法】：Padding (行填充技巧)
// 將二維陣列宣告為 32 x 33，每行多補 1 個元素，錯開對齊！
__shared__ float s_data_padded[32][33];
float safe_val = s_data_padded[threadIdx.x][0]; // 完美消除 Bank Conflict！

4. Warp 排程機制與 SIMT 執行模型

4.1 32 執行緒的 Warp 物理本質

在硬體層面，SM 從來不會單獨排程或執行「1 個 Thread」。SM 執行的絕對原子單位是 Warp（固定 32 個 Thread）。所有硬體資源（暫存器分配、指令發射、分支遮罩）皆以 32 為單位進行量化。

4.2 Warp 分歧 (Warp Divergence) 及其代價

當程式碼中出現條件分支（如 if (threadIdx.x % 2 == 0)）時，Warp 內部的一半執行緒走向 true 分支，另一半走向 false 分支：

  • 在傳統 CPU 上，多核心各自獨立執行分支，互不影響。
  • 在 GPU SIMT 架構下，同一個 Warp 只有一個指令解碼與發射單元。因此硬體必須序列化執行兩個分支：首先將走向 false 的執行緒設為禁能（Mask off），執行 true 分支；接著反轉遮罩，執行 false 分支。
  • 結果：該 Warp 的整體執行時間等於兩條分支時間之和，有效算力減半！

4.3 全域記憶體合併訪問 (Memory Coalescing)

GPU 全域記憶體（HBM3e 或 GDDR6X）不是以 Byte 為單位進行讀取的，而是以 32-Byte 或 128-Byte 的快取行（Cache Line Transaction） 為單位進行傳輸。

當一個 Warp 內的 32 個執行緒同時存取 Global Memory 時：

  • 合併存取 (Coalesced)：若 32 個執行緒存取的記憶體位址剛好落在一個連續的 128-Byte 對齊區塊內（例如 float data[threadIdx.x]），硬體只需要發起 1 次 128-Byte 的記憶體交易（Transaction），匯流排利用率達 100%。
  • 未合併存取 (Uncoalesced / Strided)：若每個執行緒存取的位址跨度很大（例如存取矩陣的某一列，跨度為步長 1024），32 個執行緒的位址分散在 32 個不同的 128-Byte Cache Line 中，硬體必須發起 32 次獨立的 128-Byte 交易。傳輸了 $32 \times 128 = 4096$ Bytes 的資料，卻只使用了其中的 $32 \times 4 = 128$ Bytes，有效頻寬利用率慘跌至 3.125%！

6. CUDA 軟體抽象與編程模型

CUDA（Compute Unified Device Architecture）是 NVIDIA 構築其不可撼動商業護城河的核心資產。CUDA 將底層硬體細節映射為優雅的三層軟體階層：

💻 軟體抽象層 (Software View)
  • Thread：最基本的邏輯運算執行緒
  • Warp：32 個 Thread 組成的鎖步群組
  • Thread Block：一組共同協作的 Threads (1~1024)
  • Grid：執行整個 Kernel 的 Block 網格
⚡ 實體硬體層 (Hardware Mapping)
  • CUDA Core / ALU：執行單一執行緒純量指令
  • SIMT Unit：Warp Scheduler 廣播發射單元
  • Streaming Multiprocessor (SM)：容納並執行 Block
  • Whole Device (GPU Chip)：排程發射整個 Grid

6.1 常用內核關鍵字與記憶體限定詞

  • __global__：在 Host (CPU) 端呼叫，在 Device (GPU) 端執行。必須回傳 void，非同步發射。
  • __device__：在 Device 端呼叫且在 Device 端執行，無法從 Host 直接調用。
  • __host__：標準 CPU 函數（若同時修飾 __host__ __device__，編譯器將產生兩份二進位程式碼）。
  • __shared__：宣告於 Block 共享記憶體中的變數，所有線程可見，生命週期與 Block 相同。
  • __constant__：宣告於 64KB 常數記憶體空間，具備單一週期廣播機制，生命週期伴隨整次執行。

6.2 Warp Shuffle 暫存器免鎖交換指令

在 Kepler 架構之前，Warp 內的執行緒若要交換數據，必須先將數據寫入 Shared Memory，呼叫 __syncthreads() 同步，再從 Shared Memory 讀取。

Warp Shuffle 指令（如 __shfl_down_sync） 的出現徹底顛覆了這一流程：它允許 Warp 內部的 32 個執行緒直接跨暫存器相互讀取數據，無需經過 Shared Memory，零 Bank Conflict，僅需 1 個 Clock Cycle！ 

// 使用 Warp Shuffle 實現極速 32-Thread 規約求和 (Warp Reduction)
__inline__ __device__ float warpReduceSum(float val) {
    #pragma unroll
    for (int offset = 16; offset > 0; offset /= 2) {
        // 遮罩 0xffffffff 代表 Warp 內全部 32 個執行緒皆參與同步
        val += __shfl_down_sync(0xffffffff, val, offset);
    }
    return val; // Lane 0 最終持有整組 Warp 的總和！
}

7. CUDA 記憶體優化與非同步串流

7.1 Pinned Memory 與計算通信重疊 (Overlapping)

標準 malloc() 分配的 CPU 記憶體為分頁記憶體（Pageable Memory），作業系統隨時可能將其置換至硬碟 Swap。當透過 cudaMemcpy() 傳輸時，CUDA 驅動程式必須先將資料複製到暫時的鎖頁記憶體（Pinned / Page-Locked Memory），再經由 DMA 控制器推送至 GPU。

直接使用 cudaHostAlloc() 配置 Pinned Memory 可以跳過中介複製，直接啟用 PCIe/NVLink 匯流排的極速 Direct Memory Access（DMA）。

透過多個 CUDA Streams（非同步運算串流），可完美實現「傳輸下一個 Batch 的資料」與「計算當前 Batch 的 Kernel」在硬體管線上的並行重疊（Compute-Communication Overlapping）： 

// 雙緩衝雙串流管線化傳輸與計算
cudaStream_t stream0, stream1;
cudaStreamCreate(&stream0);
cudaStreamCreate(&stream1);

// 串流 0 複製 Batch 0，串流 1 複製 Batch 1
cudaMemcpyAsync(d_A0, h_A0, size, cudaMemcpyHostToDevice, stream0);
cudaMemcpyAsync(d_A1, h_A1, size, cudaMemcpyHostToDevice, stream1);

for (int step = 0; step < total_steps; ++step) {
    // 串流 0 計算 Kernel 0 (同時串流 1 可以非同步拷貝下一個區塊)
    gemmKernel<<>>(d_A0, d_B0, d_C0);
    cudaMemcpyAsync(h_C0, d_C0, size, cudaMemcpyDeviceToHost, stream0);
    cudaMemcpyAsync(d_A0, h_nextA0, size, cudaMemcpyHostToDevice, stream0);

    // 串流 1 計算 Kernel 1
    gemmKernel<<>>(d_A1, d_B1, d_C1);
    cudaMemcpyAsync(h_C1, d_C1, size, cudaMemcpyDeviceToHost, stream1);
    cudaMemcpyAsync(d_A1, h_nextA1, size, cudaMemcpyHostToDevice, stream1);
}

7.2 CUDA Graph：終結 CPU 發射開銷

在深層神經網路（如數百層 Transformer）的推論過程中，許多運算子耗時極短（僅數微秒），但 CPU 透過驅動程式發射單一 Kernel 的延遲高達 3~5 微秒。這導致 GPU 在大部分時間處於「等待 CPU 餵指令」的飢餓狀態（CPU-Bound）。

CUDA Graph 允許開發者將一連串 Kernel Launch、記憶體拷貝、事件等待錄製為一張靜態執行圖（DAG）。錄製完成後，CPU 只需要發起一次 API 調用（cudaGraphLaunch），GPU 內建的硬體排程微碼引擎便能自動接管整張圖的高速重播，發射開銷直接降低 90% 以上！

8. 實戰手寫高效能 GEMM Kernel 優化

通用矩陣乘法（GEMM: General Matrix Multiply, $C = \alpha A \times B + \beta C$）是整個人工智慧與數值線代的核心基石。本節展示從天真的 Naive 實作，到利用 Shared Memory 進行 2D Tile 切塊優化的完整遞進過程：

8.1 Naive GEMM (計算訪存比極低，嚴重 Memory-Bound)

// 天真實現：每個執行緒負責計算矩陣 C 的一個元素
__global__ void naiveGemmKernel(const float* __restrict__ A,
                               const float* __restrict__ B,
                               float* __restrict__ C,
                               int M, int N, int K) {
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;

    if (row < M && col < N) {
        float sum = 0.0f;
        for (int k = 0; k < K; ++k) {
            // 每次迴圈都需要存取全局記憶體 (400+ cycles 延遲)！
            // 同一行/列的資料被不同線程重複從 Global Memory 讀取 K 次
            sum += A[row * K + k] * B[k * N + col];
        }
        C[row * N + col] = sum;
    }
}

8.2 2D Shared Memory Block Tiling GEMM (工程標準版)

透過將矩陣 $A$ 與 $B$ 切割為 $32 \times 32$ 的小塊（Tiles），載入 Shared Memory，重複利用快取資料，大幅降低對 Global Memory 的頻寬壓迫： 

#define TILE_DIM 32

__global__ void tiledGemmKernel(const float* __restrict__ A,
                               const float* __restrict__ B,
                               float* __restrict__ C,
                               int M, int N, int K) {
    // 分配片上靜態共享記憶體
    __shared__ float s_A[TILE_DIM][TILE_DIM];
    __shared__ float s_B[TILE_DIM][TILE_DIM];

    int bx = blockIdx.x, by = blockIdx.y;
    int tx = threadIdx.x, ty = threadIdx.y;

    int row = by * TILE_DIM + ty;
    int col = bx * TILE_DIM + tx;

    float acc = 0.0f;

    // 外層迴圈：以 TILE_DIM 步長橫跨 K 維度
    int numTiles = (K + TILE_DIM - 1) / TILE_DIM;
    for (int t = 0; t < numTiles; ++t) {
        // 1. 協同將當前 Tile 載入 Shared Memory (合併訪問 Coalesced)
        int aCol = t * TILE_DIM + tx;
        int bRow = t * TILE_DIM + ty;

        s_A[ty][tx] = (row < M && aCol < K) ? A[row * K + aCol] : 0.0f;
        s_B[ty][tx] = (bRow < K && col < N) ? B[bRow * N + col] : 0.0f;

        // 2. 設置記憶體屏障，確保整個 Block 的 1024 個線程都完成載入
        __syncthreads();

        // 3. 在片上極速 SRAM 中進行 TILE 級乘加累加
        #pragma unroll
        for (int k = 0; k < TILE_DIM; ++k) {
            acc += s_A[ty][k] * s_B[k][tx];
        }

        // 4. 再次同步，防止較快的線程提前覆蓋下一輪迭代的 Shared Memory
        __syncthreads();
    }

    // 5. 寫回結果至 Global Memory
    if (row < M && col < N) {
        C[row * N + col] = acc;
    }
}

9. 跨晶片與跨節點極限互連 (NVLink, NVSwitch 與 GB200 NVL72)

當單一晶片的電晶體數量逼近摩爾定律極限時，算力擴展的戰場便全面轉移至晶片間互連（Interconnect Fabric）。

9.1 PCIe 瓶頸 vs. NVLink 5.0 霸權

標準伺服器採用的 PCIe Gen 5 x16 雙向頻寬僅有 128 GB/s，對於動輒傳輸數十 GB 權重的大模型分散式 All-Reduce 通訊簡直是杯水車薪。

NVIDIA 開發的 NVLink 是特製的高速點對點序列互聯總線：

  • Hopper NVLink 4.0：單卡提供 900 GB/s 雙向頻寬（約為 PCIe 5 的 7 倍）。
  • Blackwell NVLink 5.0：單卡提供 1.8 TB/s 雙向頻寬，每條通道傳輸速率高達 224 Gbps PAM4。
  • NVSwitch 晶片：允許機櫃內所有 GPU 透過全橫截面無阻塞交叉交換矩陣進行記憶體語意直通存取（SHARP: In-Network Computing 網內硬體規約計算）。

9.2 液冷神機：GB200 NVL72 巨型單一虛擬 GPU

Blackwell 世代最具代表性的架構當屬 NVIDIA GB200 NVL72。它不是單純的 72 張加速卡堆疊，而是透過 5,184 條專用高速銅纜背板，將 36 顆 Grace CPU 與 72 顆 Blackwell GPU 徹底融合為單一巨大計算實體：

  • 全銅纜無損背板：機櫃內部放棄光模組，完全採用被動直連銅纜（DAC），節省超過 20,000 瓦功耗。
  • 雙向聚合雙向頻寬：高達 130 TB/s（相當於整個互聯網主幹即時流量的數倍）。
  • 推論算力：提供 1,440 PFLOPS（1.44 Exaflops）的 FP4 推論算力，單一機櫃即可直接在顯存內裝載並運行 27 萬億參數的巨型專家混合模型（MoE）！
