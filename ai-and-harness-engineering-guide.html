一、前言與範式轉移：開源自主 Agent 的雙雄時代

在大型語言模型（LLM）的演進歷程中，軟體工程經歷了兩次決定性的範式躍遷（Paradigm Shift）：

  1. Chatbot 時代（Token Generator）：模型僅扮演「次單詞機率預測器」，被動接收上下文並輸出自然語言文本，缺乏與真實物理或虛擬世界的互動能力。
  2. Agentic 時代（Action Engine & Harness）：模型進化為「自主決策大腦」，具備自主規劃（Plan）、工具調用（Act）、觀察反思（Observe & Reflect）、狀態持久化與目標導向執行力。

然而，大模型的本質是非確定性的（Stochastic）。若直接將隨機生成的指令送入真實作業系統、生產資料庫或外部 API，無異於將火箭點火開關交給隨機數生成器。這正是 Agent Harness（測試與執行防護約束框架） 誕生的根本原因。

在開源自主 Agent 領域，兩大代表性技術棧奠定了現代開源 Agent 的基石：

🏛️

Nous Research Hermes

模型原生推理與強結構化調用哲學

核心哲學：「大腦本身必須深刻理解工具與約束」。由 Nous Research 團隊訓練，Hermes 3 / Hermes Agent 跳脫了雲端 API 的黑盒束縛，透過高品質微調與專屬 XML 特殊標記，讓模型在未經外部提示詞大幅污染的情況下，達成媲美 GPT-4o 的極致 Tool Calling 精準度與無審查推理深度。

  • ⚡ 專屬協定：<tools>、<tool_call>、<scratchpad> 原生標記。
  • 🔌 標準適配：深度整合 Anthropic 推出的 MCP (Model Context Protocol)。
  • 💻 執行載體：Hermes CLI Daemon、Hermes Desktop、原生 Function Call 伺服器。
🦞

OpenClaw 2.0

Gateway-First 全渠道自動化調度哲學

核心哲學：「Agent 的價值在於無所不在的連接與行動力」。OpenClaw 專注於打通數位生活的全觸角，建構了一個極其強悍的 Gateway 網關架構，原生串接 Telegram、Discord、WhatsApp、Slack、Web、Desktop 與 CLI，並自帶超過 29+ 款生產級 Skills 與無頭瀏覽器執行沙箱。

  • 🌐 全渠道網關：單一 Agent 同步跨 Telegram、Discord、Slack 響應。
  • 🛡️ Execution Harness：具備完整的命令 AST 語法攔截與容器隔離。
  • 🦾 自動化引擎：整合 Playwright 網頁自動化爬蟲、系統 Bash 與檔案管線。
工程師洞察：Hermes 解決了 "How the Brain Thinks and Formats Actions"（大腦如何結構化推理與決策）；而 OpenClaw 解決了 "How the Body Connects, Shields, and Executes"（身體如何跨渠道路由、沙箱防護與執行）。理解兩者的架構精髓，是構建現代高可靠自主 Agent 的必修課。

二、Nous Hermes 核心技術深度解密：模型原生 Tool Calling 與結構化推理

1. 標記協議演進：為什麼 XML 特殊標記優於 JSON-in-JSON？

在傳統商用 API（如 OpenAI 早期 function_calling）中，工具調用通常被包裝在 JSON 字串中傳輸。這帶來了嚴重的工程痛點：

  • 雙重轉義問題（Escape Hell）：當工具參數包含正則表達式、Shell 腳本或多行程式碼時，反斜線 \ 和引號 \" 會被多次轉義，極易造成模型輸出 JSON 語法損毀。
  • 流式局部解析障礙（Streaming Token Blocking）：JSON 是一個非自定界的結構，必須等到閉合花括號 } 完整生成後，標準 JSON.parse 才能開始執行。

Nous Research 在訓練 Hermes 2 Pro 及旗艦 Hermes 3 時，開創性地將結構化標記內化為模型原生的 Special Tokens：

<tools>
[
  {
    "type": "function",
    "function": {
      "name": "execute_bash",
      "description": "在沙箱容器內執行 Shell 指令並獲取 stdout 與 stderr",
      "parameters": {
        "type": "object",
        "properties": {
          "command": {"type": "string", "description": "要執行的 bash 腳本"}
        },
        "required": ["command"]
      }
    }
  }
]
</tools>
<scratchpad>
使用者要求備份資料庫並檢查容器狀態。我需要先執行 docker ps 確保容器運行，再執行 pg_dump。
</scratchpad>
<tool_call>
{"name": "execute_bash", "arguments": {"command": "docker ps --filter name=postgres --format '{{.Status}}'"}}
</tool_call>

這種格式的工程優勢極其顯著：

  • 零歧義解析（Zero-Ambiguity AST Extraction）：Harness 僅需掛載一個正則或輕量流式狀態機，偵測到 <tool_call> 開啟標籤時即可同步初始化執行管線，偵測到 </tool_call> 立即觸發異步執行。
  • 思維鏈隔離（Reasoning Segregation）：<scratchpad> 標籤天然將模型內部的「推演過程」與「執行負載」分離，避免了 CoT 思考文字意外污染工具參數。

2. Hermes 專屬 Tool Call 流式解析器實作（Python）

以下是硬核工程師在生產環境中包裝 Hermes 輸出時使用的流式解析器實作，具備語法自動容錯與修復功能：

import re
import json
from typing import Optional, Dict, Any, List

class HermesToolCallParser:
    """
    高效流式提取 Nous Hermes  標記的解析器
    具備非完整 JSON 容錯與即時 AST 轉換能力
    """
    TOOL_CALL_REGEX = re.compile(r"<tool_call>(.*?)</tool_call>", re.DOTALL)
    SCRATCHPAD_REGEX = re.compile(r"<scratchpad>(.*?)</scratchpad>", re.DOTALL)

    @classmethod
    def extract_scratchpad(cls, raw_text: str) -> Optional[str]:
        match = cls.SCRATCHPAD_REGEX.search(raw_text)
        return match.group(1).strip() if match else None

    @classmethod
    def parse_tool_calls(cls, raw_text: str) -> List[Dict[str, Any]]:
        calls = []
        matches = cls.TOOL_CALL_REGEX.findall(raw_text)
        for match in matches:
            cleaned = match.strip()
            try:
                # 嘗試標準解析
                payload = json.loads(cleaned)
                calls.append(payload)
            except json.JSONDecodeError:
                # 容錯修復：處理結尾截斷或多餘反斜線
                fixed = cls._repair_truncated_json(cleaned)
                if fixed:
                    calls.append(fixed)
        return calls

    @staticmethod
    def _repair_truncated_json(broken_json: str) -> Optional[Dict[str, Any]]:
        # 簡單閉合補齊演算法
        open_braces = broken_json.count('{') - broken_json.count('}')
        if open_braces > 0:
            broken_json += '}' * open_braces
        try:
            return json.loads(broken_json)
        except Exception:
            return None

三、OpenClaw 2.0 核心技術深度解密：Gateway-First 全渠道網關架構

相對於 Hermes 聚焦於「模型端」的推理與調用規範，OpenClaw 2.0 則是「系統與通訊端」的架構大作。其核心架構圍繞著 Gateway-First 模式構建：

1. 全渠道統一適配器矩陣（Channel Adapters Matrix）

在傳統開發中，為 Telegram、Discord、Slack 分別編寫 Bot 需要面對完全不同的 Webhook 協議、訊息長度限制（Telegram 4096 字符、Discord 2000 字符）、附件格式與權限管理。OpenClaw 的 Unified Gateway 將所有渠道抽像化為統一的 AgentEvent 與 MessageContext：

四、硬核核心：Agent Harness 工程（Test & Execution Harness）深度解密

如同航太或汽車工程中的電氣線束（Wiring Harness）負責連接傳感器並防止短路，軟體領域的 Agent Harness 是一套圍繞在隨機性 LLM 外圍的約束、安全攔截、沙箱隔離與確定性驗證工程體系。

Pillar 1：上下文與記憶束線（Context & Token Harness）

大模型的 Context Window 雖然已經擴展至 128k 甚至 1M tokens，但長上下文伴隨著「大海撈針衰減（Needle In A Haystack Decay）」與運算成本爆炸。合格的 Harness 必須具備三階動態記憶約束：

  • 滑動窗口截斷（Sliding Window with Priority Pinning）：將 System Prompt、當前活躍任務目標與最新 3 輪對話固定釘選（Pinned），中段歷史進行非同步摘要壓縮。
  • 結構化狀態快照（Deterministic State Snapshots）：將 Agent 的外部環境狀態（如目前工作目錄、打開的檔案控制代碼、環境變數）序列化為標準 JSON 注入 Context，確保重啟後無損恢復。

Pillar 2：安全防護與語法樹攔截（AST Security Guardrails）

當 Agent 擁有 execute_bash 或 python_eval 權限時，直接執行原始字串是災難的根源。現代 Agent Harness 採用抽象語法樹（AST）深層靜態分析：

import re

class BashSecurityHarness:
    """
    生產級 Agent 命令安全攔截器
    阻止破壞性指令、反彈 Shell 與敏感檔案洩漏
    """
    BLOCKED_PATTERNS = [
        r"rm\s+-rf\s+[/~]",              # 根目錄刪除
        r"mkfs",                          # 格式化磁碟
        r":\(\)\s*\{\s*:\|:&\s*\};:",    # Fork 炸彈
        r"nc\s+-[e|c]",                   # Netcat 反彈 shell
        r"/dev/tcp/\d+/\d+",              # Bash 原生 TCP 連線
        r"cat\s+.*id_rsa",                # SSH 私鑰讀取
        r"curl.*\|\s*(bash|sh)",          # 未驗證遠端腳本執行
    ]

    @classmethod
    def inspect(cls, command: str) -> tuple[bool, str]:
        for pattern in cls.BLOCKED_PATTERNS:
            if re.search(pattern, command, re.IGNORECASE):
                return False, f"SECURITY_VIOLATION: 觸發危險指令攔截規則 '{pattern}'"
        return True, "SAFE"

Pillar 3：沙箱微隔離（Container & MicroVM Sandboxing）

在 Harness 架構中，所有外部執行負載必須在微隔離環境中運作：

  • Docker / gVisor 沙箱：透過 runsc 提供使用者空間的 Linux 核心模擬，截斷有害系統呼叫（Syscall）。
  • Firecracker MicroVM：輕量虛擬化技術，5毫秒內冷啟動獨立 Linux 核心，提供硬體級別的 MMU 記憶體隔離，確保即使 Agent 被 Prompt Injection 逃逸，也無法威脅 Host 主機。

Pillar 4：確定性重播評測（Deterministic Replay & SWE-bench Harness）

在生產部署前，Harness 必須充當評測基準（Benchmark Harness）。藉由 Mock Tool Proxy 錄製每一次外部 API 回應，將隨機的網路請求轉換為 100% 確定性的本地重播測試，確保在升級底層模型時，Agent 的決策準確率具備可重複性（Reproducibility）。

八、邊緣 SLM 與蜂群進化：未來展望與工程師總結

隨著 2026 年邊緣小型語言模型（SLM）推論技術的飛躍突破，Agent 技術正在經歷前所未有的民主化變革：

  1. 模型本體輕量化（Sub-3B Super-Agents）：透過 Nous Research 等開源社群對特定工具鏈（Tool Chains）與合成數據（Synthetic Data）的深度蒸餾，1.5B ~ 3B 參數量級的小模型已能在特定沙箱內展現高達 90% 以上的 Tool Calling 精準度。
  2. 蜂群協同與層級 Harness（Multi-Agent Swarm Harness）：未來的架構不再依賴單一龐大的全知模型，而是由 OpenClaw Gateway 同步調度多個專責 Agent：一個 Hermes 負責架構分析與程式碼審查、一個專責瀏覽器爬蟲、一個專責資料庫維運，彼此透過嚴格的 API Contract 通訊，由最外層的 Master Harness 統籌安全防線。

工程師總結心法：沒有約束的大模型只是玩具，擁有堅固 Harness 的大模型才是生產力武器。無論你選擇以 Hermes 的極致推理為核心，還是選擇 OpenClaw 的全渠道自動化為基底，牢記「模型管思考、Harness 管安全、網關管連接」的三層架構法則，你便能駕馭這場自主 AI 的世紀浪潮！
