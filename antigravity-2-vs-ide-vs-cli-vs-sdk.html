1. 典範轉移：從單點代碼補全到四大形態

過去幾年，軟體工程界經歷了從「單行代碼補全 (Copilot Style)」邁向「自主智能代理 (Agentic Coding)」的巨大典範轉移。傳統 AI 工具僅僅是在編輯器游標旁插入程式碼，而現代的 AI 代理則擁有自主讀取跨檔案程式碼庫、執行終端機指令、建構與執行測試、抓取即時文檔、甚至自我除錯反思的完整閉環能力。

然而，面對多元的軟體工程實務場景，單一的使用者介面 (UI) 已經無法滿足現代工程師的全光譜需求：

  • 架構師與團隊主管需要站在宏觀視角，同時調度多個代理執行跨專案重構、非同步審查設計文件與產生的 Artifacts，這需要獨立的控制台畫布；
  • 第一線業務工程師需要極致的鍵盤手感，在程式碼撰寫過程中無縫獲得意圖預測補全、行內選區就地重構與紅綠 Diff 審核，這需要緊密整合於編輯器內部；
  • DevOps 與雲端維運工程師常駐於無圖形介面的遠端 SSH 伺服器、Docker 容器或 CI/CD 管線，需要極低記憶體佔用、次秒級啟動且能以 Unix Pipeline 串接的命令列工具；
  • AI 系統架構師與自動化工程師則需要將代理能力直接封裝進 Python 服務、自動化評測腳本、監控機器人或企業自研的多代理流水線中，這需要開箱即用、原生二進位編譯的高效軟體開發套件 (SDK)。

為了解決這四大截然不同的工程需求，Google Antigravity 生態系演化出了「四大支柱 (The Four Pillars)」：Antigravity 2.0 (Desktop)、Antigravity IDE、Antigravity CLI (agy)，以及 Antigravity Python SDK (google-antigravity)。本文將以深度的硬核工程視角，逐一拆解這四大形態的底層架構、運作機制、適用場景與串接實踐！

3. 支柱一：Antigravity 2.0 (獨立多代理指揮中心)

Antigravity 2.0 是一個基於 Electron 構建的獨立桌面應用程式。它的核心設計哲學是「脫離特定編輯器的綁定，打造全知視角的多代理 (Multi-Agent) 指揮中樞」。在 Antigravity 2.0 中，工程師不再只是打字的碼農，而是扮演調度多個代理專家協同作業的「總指揮」。

A. 雙欄式佈局與核心交互區域

  • Left-hand Sidebar (左側控制導航欄)：
    • New Conversation：隨時建立獨立上下文的代理會話，支援並行開啟多個主題對話。
    • Projects：多儲存庫 (Multi-Repo) 與工作區切換器，每個專案各自維護獨立的設定與權限覆蓋。
    • Scheduled Tasks：背景定期維運排程中心，支援標準 5 段式 Cron 表達式與一次性延遲計時器。
    • Skills & Customizations：集中檢視全域與工作區專屬的 Skills、Rules、Plugins 及 MCP 伺服器連線狀態。
    • Settings：階層式設定中心，包含模型選型、工具自動執行政策與全域安全沙箱。
  • Chat Canvas (中央交談與推理畫布)：
    • 專用 Slash Commands：內建 /goal（極限長程過夜任務）、/plan（嚴謹多階段規劃）、/schedule（定時任務排程）、/grill-me（架構方案反向壓力訪談）與 /learn（行為模式沉澱學習）。
    • @ 上下文提及 (Mentions)：可一鍵將檔案、資料夾、過往歷史會話、終端機 Session、系統 Rules 或特定 MCP 工具精準掛載至當前上下文。
    • 多模態媒體原生拖放：支援直接拖放截圖、架構設計圖、UI Mockup，Agent 會自動進行視覺推理並生成前端實作代碼。
  • Auxiliary Pane (右側輔助作業面板)：
    • Subagents 面板：實時視覺化當前主代理派生出的子代理樹狀結構，監控各子代理的執行進度與狀態。
    • Background Tasks 面板：監控並行執行的長時間背景建構、本地伺服器、單元測試進程。
    • Artifacts 面板：高階渲染架構文檔、測試報告、可互動預覽元件與版本 Diff，並提供審查反饋按鈕。
    • Files Changed 面板：集中檢視代理在當前會話中修改過的所有檔案，提供單一檔案或批次 Revert 功能。
    • Sandboxed Terminals：內建分離式終端視窗，即時展示終端輸出與沙箱執行記錄。

B. 企業級安全策略與雙層權限模型

在自動化執行終端命令與檔案寫入時，安全永遠是第一考量。Antigravity 2.0 提供了業界最完善的階層式權限防禦體系：

Global Settings (全域政策基準)
   └── Project Settings (專案層級覆蓋政策)
         ├── Tool Execution Policy: [always-proceed | request-review | strict | proceed-in-sandbox]
         ├── Non-Workspace File Access: [allow | ask | deny]
         ├── Internet Access Policy: [allow | ask | deny]
         ├── Terminal Sandbox: 啟用命名空間與虛擬隔離環境
         ├── Command Allowlist / Denylist: 強制封鎖危險指令 (如 rm -rf /)
         └── Browser Allowlist: 嚴格限制瀏覽器代理僅能訪問內部特定網域

4. 支柱二：Antigravity IDE (AI 原生沉浸式編輯器)

與 Antigravity 2.0 的宏觀指揮不同，Antigravity IDE 選擇將 AI 的神經網絡直接編織進工程師的擊鍵與游標之中。基於 VS Code / Code-OSS 核心架構打造，專為追求極致打字心流與毫秒級回饋的開發者設計。

A. 三層次核心 AI 交互模態 (The 3 AI Modalities)

  • Tab to Jump：自動預測游標下一步該跳轉的位置，按一下 Tab 直接定位。

B. 編輯器原生深度功能整合

  • Inline Code Lenses (行內操作鈕)：在類別與函數定義上方自動浮現 [Refactor]、[Write Tests]、[Explain Code] 按鈕，點擊即可針對該符號喚醒代理。
  • Diagnostic Auto-Fix (語法錯誤自動修復)：當編譯器報錯或 ESLint 出現紅色波浪線時，滑鼠懸浮在錯誤上直接點擊「Auto-fix with Agent」，代理會即時解析錯誤堆疊並應用修復代碼。
  • Workspace-Scoped Config (專案自動發現)：自動辨識專案根目錄下的 .agents/ 資料夾，載入專屬的 Rules（編碼規範）與 Skills（技能腳本）。

5. 支柱三：Antigravity CLI (終端極速輕量引擎)

對於深度的終端愛好者、Vim/Neovim 鍵盤流開發者、以及維運遠端伺服器的 SRE 而言，GUI 應用程式往往過於笨重。Antigravity CLI (agy) 正是為終端速度 (Terminal Velocity) 與輕量自動化而生的極速終端引擎。

A. 核心優勢與終端哲學

  • 次秒級冷啟動：沒有 Electron 或 Chromium 的肥大開銷，終端輸入 agy 瞬間進入交談介面。
  • 超低記憶體佔用：常駐記憶體僅數十 MB，相較於桌面 IDE 節省了超過 90% 的 RAM，在 1GB 記憶體的輕量 VPS 或雲端邊緣伺服器上也能流暢運作。
  • SSH 與無圖形 (Headless) 環境友好：在雲端虛擬機 (EC2, GCP Compute Engine, Kubernetes Pod) 中，直接透過 SSH 即可流暢執行，完全不依賴 X11 Forwarding 或遠端桌面協定。

B. Unix 哲學：管道 (Pipeline) 與腳本串接實戰

agy 完美繼承了 Unix「做一件事並把它做好」與標準輸入輸出 (stdin/stdout) 的哲學，能像 grep 或 awk 一樣被組合進任何 Shell 腳本：

# 範例 1：分析生產環境 Nginx 崩潰日誌
$ tail -n 100 /var/log/nginx/error.log | agy "分析這段錯誤日誌中的關鍵崩潰原因並給予修復建議"

# 範例 2：一鍵生成符合 Conventional Commits 規範的 Git 提交訊息
$ git diff --staged | agy "依 Conventional Commits 格式撰寫簡短 commit message" | git commit -F -

# 範例 3：針對當前系統架構自動產生 Kubernetes Deployment YAML
$ agy "生成一個具備 3 個 replica、健康檢查與資源限制的 nodejs k8s deployment yaml" > k8s-deploy.yaml

# 範例 4：非互動批次模式執行程式碼檢查
$ agy -p "檢查 src/ 目錄中是否有任何硬編碼的密碼或 API Key"

CLI 的全域設定檔儲存於 ~/.gemini/antigravity-cli/settings.json，可用於設定預設模型、終端色彩偏好與 API 逾時時間。

6. 支柱四：Antigravity SDK (程式化智慧與自動化核心)

如果說前三者是讓「人類透過不同介面與 Agent 互動」，那麼 Antigravity Python SDK (google-antigravity) 則是讓「軟體程式能夠自主擁有 Agentic 智商」！它是將 Antigravity 代理能力無縫嵌入後端微服務、CI/CD 自動化管線、企業內部系統與自訂多代理架構的基礎建設。

📦 官方套件資訊：
GitHub 開源儲存庫：google-antigravity/antigravity-sdk-python
安裝指令：pip install google-antigravity（依賴發布在 PyPI 上的原生二進位輪子平台）。

A. 核心架構設計：非同步生命週期與最小權限模型

SDK 透過 Agent 非同步上下文管理器 (Async Context Manager) 管理代理的完整生命週期（原生執行時發現、工具綁定、Hook 註冊與政策設定）。為確保安全性，SDK 預設在唯讀 (Read-only) 模式下運行，必須明確傳入 CapabilitiesConfig() 才能解鎖寫入工具（如 run_command、edit_file、write_to_file）：

import asyncio
import sys
from google.antigravity import Agent, LocalAgentConfig, CapabilitiesConfig

async def main():
    # 1. 建立配置：設定系統提示詞，並啟用完整執行能力 (Capabilities)
    config = LocalAgentConfig(
        system_instructions="你是一位專精於分散式架構與代碼審查的資深工程師。",
        capabilities=CapabilitiesConfig(), # 解鎖寫入工具與命令執行
    )

    # 2. 透過 async with 安全啟動 Agent 生命週期
    async with Agent(config) as agent:
        # 3. 發送非同步任務提示詞 (立即回傳，不阻塞執行緒)
        response = await agent.chat("請檢視目前的專案目錄結構，並產生一個簡單的健康檢查 API。")

        # 4. 即時逐 Token 串流輸出
        async for token in response:
            sys.stdout.write(token)
            sys.stdout.flush()
        print()

if __name__ == "__main__":
    asyncio.run(main())

B. 高階特性：即時思考串流與強型別 ToolCall 攔截

在進階的企業級應用中，工程師往往需要監控 Agent 的內部思考推論鏈 (Chain-of-Thought)，或者在 Agent 呼叫終端指令與寫檔前進行程式化審核與參數攔截。SDK 提供了原生強型別串流事件支援：

# 1. 即時串流監聽 Agent 的內部思考過程 (Thinking / Reasoning Stream)
async for thought in response.thoughts:
    print(f"🧠 [Agent 思考推論中] {thought}")

# 2. 串流攔截強型別工具執行 (ToolCall Interception)
async for call in response.tool_calls:
    print(f"⚙️ [工具調用觸發] 呼叫工具: {call.name}")
    print(f"📦 [傳入參數細節] {call.args}")
    
    # 範例：程式化自訂安全守門員
    if call.name == "run_command" and "rm" in call.args.get("CommandLine", ""):
        print("🚨 警報：檢測到危險刪除指令，自動終止執行！")
        break

C. 企業級自動化實戰：自建 GitHub Actions 程式碼審查機器人

透過 Antigravity Python SDK，你只需要短短數十行程式碼，就能在 CI/CD 中打造出能夠理解整個程式碼庫架構的自動審查機器人：

import asyncio
import os
import subprocess
from google.antigravity import Agent, LocalAgentConfig

async def review_pull_request():
    # 抓取目前分支相對於 main 分支的改動 Diff
    diff_output = subprocess.check_output(["git", "diff", "origin/main...HEAD"]).decode("utf-8")
    
    config = LocalAgentConfig(
        system_instructions="你是一位頂尖的資安與效能專家，請針對 PR Diff 找出潛在 Memory Leak 與資安弱點。"
    )

    async with Agent(config) as agent:
        prompt = f"請詳細審查以下 PR Diff，並列出嚴重的安全性與效能問題：\n\n```diff\n{diff_output}\n```"
        response = await agent.chat(prompt)
        
        review_comments = []
        async for token in response:
            review_comments.append(token)
            
        full_review = "".join(review_comments)
        print("=== CI PR 審查報告 ===")
        print(full_review)
        
        # 可進一步呼叫 GitHub API 自動將 full_review 留言至 PR！

if __name__ == "__main__":
    asyncio.run(review_pull_request())

9. 四位一體極限開發流水線 (Quad-Workflow)

真正的硬核工程團隊從不局限於單一工具，而是讓四大形態在軟體開發生命週期 (SDLC) 的不同階段各展所長，構築全自動化的工程閉環：

Phase 1：清晨 06:00 — Antigravity 2.0 負責背景排程巡檢

利用 Antigravity 2.0 內建的 Scheduled Tasks (Cron)，在無人值守的情況下自動啟動背景代理：

  • 自動拉取 upstream 最新代碼與依賴漏洞庫公告。
  • 執行靜態代碼分析，自動標記 deprecated 函數並產生架構改善計畫 (Plan Artifact)。
  • 工程師 09:00 上班開機，直接在右側 Auxiliary Pane 驗收巡檢報告。

Phase 2：工作時間 09:30 — Antigravity IDE 負責高頻心流寫碼

打開 Antigravity IDE，進入專注的編碼狀態：

  • 寫 Controller 或 Service 邏輯時，依賴 Antigravity Tab 預測補全型別與 DTO 映射。
  • 遇到複雜邏輯，選取區塊按下 Ctrl+I：「將此同步呼叫改寫為異步非阻塞管線並加入防禦型驗證」。
  • 遇到單元測試紅燈，點擊報錯旁的 Diagnostic Auto-Fix，Agent 秒修語法偏差。

Phase 3：下午 15:00 — Antigravity CLI (agy) 負責極速提交與伺服器除錯

功能開發完畢，切換至終端機發揮 agy 的極速管道實力：

# 1. 產生合規 Commit Message
$ git diff --staged | agy "依 Conventional Commits 撰寫 commit message" | git commit -F -

# 2. SSH 到 Staging 測試機排查部署問題
$ ssh staging-node "docker logs auth-api --tail 100 | agy '檢查 JWT 過期重整問題'"

Phase 4：傍晚 17:30 — Antigravity SDK 負責 CI/CD 門禁與微服務治理

當 Pull Request 推送至 GitHub 時，觸發後端 Python SDK 建立的自動化管線：

  • SDK 程式自動掛載 PR Diff，並透過 response.thoughts 記錄完整的推理分析鏈。
  • 程式化攔截資安風險與潛在記憶體洩漏，自動發表審查評論並決定是否阻擋合併。

10. 常見技術問答 (FAQ)

Q1: Antigravity 2.0 與 Antigravity IDE 可以同時開啟同一個專案嗎？

完全可以！兩者共享相同的底層檔案系統與 .agents/ 自訂設定（Rules, Skills, MCP Servers）。許多資深工程師的日常雙螢幕配置，就是左邊螢幕開啟 Antigravity 2.0 負責大範圍規劃與後台測試，右邊螢幕開啟 Antigravity IDE 進行精準編碼。

Q2: Python SDK 與 Antigravity CLI 的底層二進位引擎相同嗎？

是的。兩者都基於 Google Antigravity 高效能原生 C++/Go 編譯執行時。SDK 透過 PyPI 的 platform-specific wheel 打包該執行時，並透過非同步通訊協定封裝為 Pythonic API，因此兩者在推論速度與工具執行效率上具備一致的極致效能。

Q3: 在無 GUI 的 Linux 雲端伺服器上，我該選擇 CLI 還是 SDK？

如果是人類工程師進行互動除錯或撰寫臨時 Shell 腳本，首選 CLI (agy)；如果是自動化後端服務、定時排程 Cron 服務、或者 CI/CD Pipeline 腳本，首選 SDK (google-antigravity)，因為 SDK 提供了結構化的程式碼控制、非同步例外處理與強型別事件監聽。

Q4: 使用 SDK 時如何避免 Agent 誤刪伺服器上的關鍵檔案？

SDK 預設採用嚴格的最小權限設計：LocalAgentConfig() 在不傳入 capabilities 時處於完全唯讀 (Read-Only) 狀態。即使你啟用了 CapabilitiesConfig()，也可以透過監聽 response.tool_calls 串流，在程式碼層面即時攔截並拒絕任何不符合白名單規則的指令！
