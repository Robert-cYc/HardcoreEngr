1. 為什麼選擇 Ollama？底層架構與核心優勢

在本地運行開源大語言模型（如 DeepSeek-R1、Llama 3.3、Qwen 2.5、Mistral）的世界中，底層技術實質上由著名開源專案 llama.cpp（以純 C/C++ 編寫的推理引擎）所統治。然而，編譯 llama.cpp、手動配置 CUDA 鏈路、設定 GGUF 分割檔案與調整繁雜的超參數，對大多數工程師與開發者而言門檻極高。

Ollama 的出現，就如同 Docker 之於 Linux 容器技術：

  • 統一封裝格式（Model Manifest）：將權重檔、量化參數、Prompt 模板、System Prompt 與推理超參數整合成單一模型單元。
  • 智慧硬體加速偵測：自動偵測 NVIDIA CUDA、AMD ROCm、Apple Silicon Metal 以及 Intel oneAPI，自動完成跨層卸載（GPU Offload）。
  • 背景守護進程與 REST API：開機自動常駐，原生暴露標準 HTTP API，更內建了與 OpenAI 相容的 /v1 端點。
  • 零資料外洩、零 API 費用：所有 Token 生成均在本地晶片完成，徹底杜絕企業機密或代碼外流。

2. 三大平台安裝與背景守護進程管理

2.1 macOS 安裝（Apple Silicon 首選）

在配備 M 系列晶片（M1/M2/M3/M4）的 Mac 上，Ollama 能夠直接利用 Apple 的統一記憶體架構（Unified Memory Architecture），GPU 與 CPU 共享高達數百 GB/s 的記憶體頻寬，是體驗 70B 大模型的性價比神器。

# 推薦使用 Homebrew 安裝
brew install ollama

# 啟動 Ollama 背景服務
ollama serve

亦可至官網下載 Ollama-darwin.zip，將 Ollama.app 拖入應用程式資料夾即可常駐選單列。

2.2 Windows 10/11 原生安裝

早期 Ollama 依賴 WSL2，如今已提供完全原生的 Windows 安裝包，直接調用本機 NVIDIA / AMD 顯示卡驅動：

  1. 前往 Ollama 官網 下載 OllamaSetup.exe。
  2. 執行安裝後，工作列右下角會出現羊駝圖示，表示服務已在 127.0.0.1:11434 成功監聽。
  3. 開啟 PowerShell 或 Windows Terminal，輸入 ollama --version 即可驗證。

2.3 Linux (Ubuntu / Debian / CentOS) 生產伺服器一鍵安裝

# 官方一鍵安裝腳本（自動配置 systemd 守護進程與 NVIDIA 驅動識別）
curl -fsSL https://ollama.com/install.sh | sh

# 管理 Ollama 服務狀態
sudo systemctl status ollama
sudo systemctl restart ollama
sudo journalctl -u ollama -f  # 即時查看推理日誌

4. VRAM 顯存精算與量化選型法則

很多初學者經常遇到「跑模型速度只有每秒 2 個 token」的窘境，本質原因就是顯存爆滿，部分權重被回退（Fallback）到慢速的 CPU 與系統記憶體。

4.1 模型顯存開銷公式

本地運行大模型，所需的實質顯存由三大塊構成：

$$\text{總顯存需求 (GB)} = \text{模型權重大小} + \text{KV Cache (上下文記憶體)} + \text{CUDA 推理開銷 (約 1~1.5GB)}$$

📦 1. 權重大小估算

在主流 Q4_K_M (4-bit 量化) 下，平均每個參數消耗約 0.55 ~ 0.6 Bytes： $$\text{7B/8B 模型} \approx 4.8 \sim 5.2 \text{ GB}$$ $$\text{14B 模型} \approx 9.0 \sim 9.5 \text{ GB}$$ $$\text{32B 模型} \approx 20.0 \sim 21.0 \text{ GB}$$ $$\text{70B 模型} \approx 42.0 \sim 44.0 \text{ GB}$$

🧠 2. KV Cache 上下文擴張開銷

上下文長度（Context Window）越長，儲存注意力鍵值對的顯存呈線性甚至二次方暴增。例如 32B 模型在 32K 上下文 下，僅 KV Cache 就需額外吞噬 4~6 GB 顯存！

4.2 主流量化等級（Quantization）對照指南

  • Q4_K_M (4-bit Medium)：Ollama 官方庫的預設黃金標準。兼顧速度、顯存與語言理解，困惑度（Perplexity）僅比全精度損失約 1%~2%。
  • Q5_K_M (5-bit Medium)：如果顯存有少許餘裕，5-bit 能在數學推理與複雜代碼生成中顯著減少幻覺。
  • Q8_0 (8-bit)：精度極度逼近 FP16，但體積接近翻倍，適合 7B/8B 小模型在 16GB 顯卡上求取極致品質。

6. 生產級環境變數深層調校 (Advanced Environment Variables)

很多工程師將 Ollama 部署到雲端或家庭伺服器時，常遇到「外網連不上」、「C 槽爆滿」、「多個請求卡死排隊」等問題。這些都可以透過環境變數完美解決！

環境變數名稱 預設值 推薦生產設定 功能說明與硬核場景
OLLAMA_HOST 127.0.0.1:11434 0.0.0.0:11434 開放跨區網監聽。讓區域網路內的手機、同事電腦或 Docker 容器能直接調用 API。
OLLAMA_ORIGINS 限制本機 "*" 解除跨域資源共享 (CORS) 限制。連接瀏覽器插件（如 Page Assist）或外部 WebUI 必配。
OLLAMA_MODELS 預設系統目錄 /data/ollama/models
或 D:\OllamaModels		 重定向大模型儲存路徑。將數十 GB 的模型搬到大容量 NVMe SSD，拯救 C 槽或根目錄。
OLLAMA_NUM_PARALLEL 1 2 或 4 啟用多併發平行請求處理。允許多位用戶同時提問而無需排隊（會成倍消耗 KV Cache 顯存）。
OLLAMA_MAX_LOADED_MODELS 1 2 或 3 顯存同時常駐模型數。例如同時在顯存加載一個 LLM 和一個 Embedding 模型，無需頻繁換入換出。
OLLAMA_KEEP_ALIVE 5m (5分鐘) 24h 或 -1 模型在顯存中的駐留時間。設為 24h 避免每次提問都要等待數秒重新加載模型權重。
CUDA_VISIBLE_DEVICES 所有 GPU 0 或 0,1 指定 Ollama 運行的特定顯卡編號，在多卡伺服器上隔離運算資源。

6.1 如何持久化設定這些環境變數？

  • Linux (systemd)： 
    sudo systemctl edit ollama.service
# 在開啟的文件中加入：
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
Environment="OLLAMA_ORIGINS=*"
Environment="OLLAMA_MODELS=/mnt/nvme/ollama"
Environment="OLLAMA_NUM_PARALLEL=4"
Environment="OLLAMA_KEEP_ALIVE=24h"

# 存檔後重載並重啟
sudo systemctl daemon-reload
sudo systemctl restart ollama
  • Windows：在「系統內容」$\to$「環境變數」$\to$「系統變數」中新增上述變數，隨後在工作列右下角完全退出 Ollama 並重新啟動。
  • macOS (GUI App)： 
    launchctl setenv OLLAMA_HOST "0.0.0.0:11434"
launchctl setenv OLLAMA_ORIGINS "*"

7. Modelfile 語法與外部 GGUF 匯入實戰

Ollama 的精髓在於類似 Dockerfile 的 Modelfile 機制。你可以自由微調系統提示詞、限制輸出長度，甚至把從 Hugging Face 下載的任意 GGUF 封裝成專屬的私有模型！

7.1 從零封裝 Hugging Face 上的自訂 GGUF

假設你從 Hugging Face 下載了一個微調過的開源量化模型 MyModel-Q4_K_M.gguf，只需建立一個名為 Modelfile 的純文字檔：

# 1. 指向本地 GGUF 檔案路徑
FROM ./MyModel-Q4_K_M.gguf

# 2. 定義對話 Prompt 模板 (以 ChatML 格式為例)
TEMPLATE """{{ if .System }}<|im_start|>system
{{ .System }}<|im_end|>
{{ end }}{{ if .Prompt }}<|im_start|>user
{{ .Prompt }}<|im_end|>
{{ end }}<|im_start|>assistant
{{ .Response }}<|im_end|>"""

# 3. 固化專業 System Prompt
SYSTEM """你是一位任職於頂尖科技公司的 Staff AI 架構師。
你的回答必須遵循：專業、直擊痛點、附帶 Production-ready 範例代碼，並使用繁體中文。"""

# 4. 推理核心超參數配置
PARAMETER temperature 0.6
PARAMETER top_p 0.95
PARAMETER top_k 40
PARAMETER num_ctx 32768
PARAMETER stop "<|im_start|>"
PARAMETER stop "<|im_end|>"

接著在終端機執行一鍵封裝：

# 構建專屬模型並命名為 my-architect
ollama create my-architect -f ./Modelfile

# 立即在終端機啟動並對話
ollama run my-architect

8. OpenAI 相容端點與現代生態系整合

Ollama 最具戰略價值的特性之一，是它內建了相容 OpenAI API 規格的端點。這意味著：任何支援自定義 OpenAI API URL 的軟體，都能無縫將遠端雲端模型替換為你的本地私有化 Ollama！

💻 Continue.dev (VS Code / JetBrains 插件)

在 ~/.continue/config.json 中配置 Ollama，讓 qwen2.5-coder:14b 成為你 IDE 內的免費 Copilot，Tab 自動補全與代碼重構完全在本地斷網運行！

🌐 Open-WebUI (媲美 ChatGPT 的頂級介面)

透過 Docker 一秒部署：
docker run -d -p 3000:8080 -e OLLAMA_BASE_URL=http://host.docker.internal:11434 ghcr.io/open-webui/open-webui:main
解鎖多模型對比、聯網搜尋、語音對話與 RAG 知識庫功能。

8.1 Python 調用 OpenAI 官方 SDK 示範

from openai import OpenAI

# 將 base_url 指向本機 Ollama 的相容端點，api_key 隨意填寫即可
client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama"
)

response = client.chat.completions.create(
    model="deepseek-r1:14b",
    messages=[
        {"role": "system", "content": "你是一個專業助手"},
        {"role": "user", "content": "請用繁體中文解釋什麼是浮點數精度損失？"}
    ],
    temperature=0.7,
    stream=True
)

for chunk in response:
    content = chunk.choices[0].delta.content
    if content:
        print(content, end="", flush=True)
print()

9. 視覺多模態與 Function Calling 工具調用

9.1 多模態視覺模型 (Vision Models) 圖片辨識實戰

Ollama 支援 llama3.2-vision、llava、minicpm-v 等多模態模型，可直接傳入本機圖片進行 OCR、圖表分析或錯誤截圖診斷：

# 下載視覺模型
ollama pull llama3.2-vision:11b

# 在命令列中直接指定圖片路徑與問題
ollama run llama3.2-vision:11b "請分析這張圖表中的趨勢與異常值：/path/to/chart.png"

9.2 結構化輸出 (Structured JSON Output)

在構建自動化工作流（Agent）時，模型輸出不穩定的純文字往往會導致後續解析爆掉。Ollama 支援 format: "json" 強制輸出合法 JSON：

curl http://localhost:11434/api/generate -d '{
  "model": "llama3.1",
  "prompt": "請擷取以下文字的姓名與年齡：小明今年28歲，住在台北市。",
  "format": "json",
  "stream": false
}'

10. 顯卡未吃滿與效能除錯指南 (Troubleshooting)

🚨 問題 1：模型運行極度緩慢，CPU 佔用 100%？

診斷： 執行 ollama ps 檢查。如果 PROCESSOR 欄位顯示 100% CPU 或 30%/70% CPU/GPU，說明顯存不足導致部分 Layer 被回退到系統 RAM。
解方： 下載更小量化等級（如 Q4_K_M 代替 Q8_0）或縮小 num_ctx 上下文長度。

⚠️ 問題 2：Linux 伺服器無法識別 NVIDIA 顯卡？

診斷： 檢查 nvidia-smi 是否正常，以及是否安裝了 nvidia-container-toolkit。
解方： 確保 systemd 服務具有讀取 GPU 裝置節點的權限，並於日誌中確認出現 CUDA compute capability discovered 字樣。
