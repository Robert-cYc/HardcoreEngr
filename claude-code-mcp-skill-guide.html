💡 閱讀前言：從聊天機器人到自主工程代理 (Autonomous Engineering Agent)

如果你依然把 AI 當成「在瀏覽器聊天室問問題，再手動複製代碼」的工具，那麼你已經落後一個世代。Claude Code 代表的是以終端機（CLI）為核心的 Agentic AI 開發新典範：它不只是生成代碼，而是具備自主執行迴圈（Observe ➔ Plan ➔ Tool Call ➔ Execution ➔ Reflection）、能夠直接讀寫本地檔案、執行測試、解析編譯錯誤並自動修復的虛擬資深工程師。

01. Claude Code 核心生態與 Agentic Loop 原理

在傳統的 LLM 應用程式中，模型處於「被動請求—回應 (Request-Response)」模式。但在 Claude Code 中，核心機制被重構為一個持續運行的自主代理狀態機 (Autonomous Agent State Machine)：

Claude Code 終端自主代理執行迴圈 (Agentic Loop)
[ 工程師輸入任務 ] ──► "幫我為 auth 模組加入 JWT Refresh Token 機制並跑單元測試" │ ▼ ┌── 1. Observe (環境感知) │ 讀取專案目錄結構、檢視 package.json、Git 狀態與相關程式碼 │ ▼ ┌── 2. Plan & Reason (推理與拆解) │ 決定需要調用的工具鏈（Tool Use Plan）：檔案讀寫、終端命令 │ ▼ ┌── 3. Tool Execution & Guardrails (工具調用與邊界防護) │ - 呼叫 Edit/Write 寫入 JWT 程式碼 │ - 觸發 PreToolUse Hook (確認無危險指令) │ - 呼叫 Bash Tool 執行 npm test │ ▼ ┌── 4. Observation & Reflection (結果審視與代碼自愈) │ - 若測試失敗 ──► 解析報錯堆疊 ──► 回到步驟 2 自主修復代碼 │ - 若測試通過 ──► 觸發 PostToolUse (Prettier 格式化) │ ▼ [ 完成任務並提交 Git Commit ]

然而，Claude 本身只是一個運算核心，它在預設情況下「只能看到本地檔案系統」與「執行本機終端指令」。當你的工程任務需要跨越本機邊界——例如：

  • 查詢 Production PostgreSQL 資料庫 Schema，比對目前代碼的模型定義是否一致；
  • 讀取 GitHub Issue 或 Jira 票券，自動獲取需求規格與驗收條件；
  • 檢索企業內部 Notion / Confluence 知識庫，獲取內部架構設計準則；
  • 操控無頭瀏覽器 (Puppeteer)，執行端到端 E2E 視覺回歸測試。

這時，傳統的 Prompt Engineering 無能為力。我們需要一個標準化的開放協定——這就是 MCP (Model Context Protocol) 的誕生由來。

02. MCP 協議架構深度剖析：Tools / Resources / Prompts

MCP (Model Context Protocol) 是 Anthropic 在 2024 年底開源的一項開放協定標準，其目標被譽為「AI 時代的 USB-C 接口」。在 MCP 出現之前，每個 AI 開發框架（LangChain、LlamaIndex、Semantic Kernel、AutoGPT）都自創了一套 Tool Call 規範，導致工具開發者必須針對不同框架寫一堆適配器 (Adapters)。

MCP 徹底統一了這個生態：只要一個服務符合 MCP 規範（MCP Server），無論是 Claude Code、Claude Desktop、VS Code 外掛或是未來的任何 AI Agent（MCP Client），都能以零代碼修改的方式直接接入。

MCP Client / Server 架構與協議通信拓撲
┌─────────────────────────┐ JSON-RPC 2.0 (stdio / SSE) │ Claude Code │ ◄────────────────────────────────────────► │ (Host / MCP Client) │ └────────────┬────────────┘ │ ┌────────┴─────────┬───────────────────┬───────────────────┐ │ │ │ │ ▼ ▼ ▼ ▼ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │ Filesystem │ │ GitHub │ │ Postgres │ │ Custom API │ │ MCP Server │ │ MCP Server │ │ MCP Server │ │ FastMCP(Py) │ └─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘ [本地受限目錄] [Issues/PR/Diff] [DB Schema/Query] [內部業務微服務]

2.1 MCP 的三大核心原語 (Core Primitives)

MCP 規範定義了三種核心能力對象，理解這三種對象的分工是掌握 MCP 的基石：

原語類型 (Primitive) 資料流向與角色 是否具副作用 (Side-effect) Claude Code 中的使用場景
Tools (工具) Model ➔ Server (主動執行)
可調用的函數，接收結構化參數並回傳結果		 有副作用 (可修改外部狀態)
需人機協同 (Human-in-the-loop) 審批		 建立 GitHub Issue、執行 SQL 寫入、發布 Slack 通知、控制瀏覽器點擊
Resources (資源) Server ➔ Model (上下文注入)
類似檔案的唯讀數據，以 URI（如 postgres://db/schema）標識		 無副作用 (純唯讀)
模型或系統可自動快取與檢索		 讀取專案依賴圖譜、查看 API 文檔、加載數據庫 Table 結構、檢視日誌串流
Prompts (提示詞模板) Server ➔ User/Model (交互預設)
預先編寫的高階 Prompt 模板與動態參數綁定		 無副作用 伺服器內建的最佳化對話範本（例如「分析該 PR 的安全風險」）

2.2 傳輸層協議 (Transports)：stdio vs SSE vs Streamable HTTP

MCP 客戶端與伺服器之間採用 JSON-RPC 2.0 封裝，底層傳輸通道支援兩種主要模式：

  • stdio (Standard Input/Output)：客戶端以子進程（Subprocess）直接啟動 Server，雙方透過標準輸入/輸出流以換行符號隔開的 JSON 進行全雙工通訊。這是本機 CLI 最推薦模式：無網路延遲、進程生命週期與 Claude Code 綁定、天然隔離外網存取，極度安全。
  • SSE (Server-Sent Events) / Streamable HTTP：用於遠端伺服器或容器化 Microservices。客戶端向遠端 MCP HTTP 端點發起 POST 發送 JSON-RPC 請求，伺服器則透過長連線 SSE 串流推送回應與事件通知。

03. MCP 安裝與配置實戰：.mcp.json 與安全隔離

在 Claude Code 中使用 MCP，最核心的設定檔就是 .mcp.json。Claude Code 支援雙層配置優先權體系：

配置層級 檔案路徑 適用範疇 團隊共享與版本控制
專案層級 (Project Scope) <專案根目錄>/.mcp.json 當前專案專屬的 MCP Servers（如本專案的 DB、自定義代碼生成器） 建議提交至 Git，供全體團隊成員開箱即用（排除敏感 Token）
全域層級 (Global Scope) ~/.claude.json 或 ~/.claude/claude_desktop_config.json 個人通用工具（如個人 GitHub 帳號、個人 Brave Search、系統監控） 個人本機專屬，不與專案綁定，跨專案自動生效

3.1 .mcp.json 的標準語法骨架

以下是一個標準且生產級的 .mcp.json 配置範例：

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/username/project/src",
        "/Users/username/project/docs"
      ]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"
      }
    },
    "postgres": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-postgres",
        "postgresql://robert:secure_pass@localhost:5432/ecommerce_db"
      ]
    }
  }
}
⚠️ 企業級安全紅線：嚴禁在 .mcp.json 硬編碼金鑰

因為 .mcp.json 通常需要提交至 Git 與團隊共享，絕對不能把生產環境密碼、AWS Key 或 GitHub PAT 直接寫死在 env 欄位中！

最佳實踐方案：

  1. 在 env 中使用變數引用："GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"，由工程師本機的 ~/.zshrc 或 .env 注入；
  2. 或者將敏感的 Server 設定在全域 ~/.claude.json 中；
  3. 利用 Claude Code 原生的 OAuth 機制：執行 claude mcp login <server-name>，憑證會安全儲存在本機 OS Keyring 中。

3.2 Claude Code 原生 CLI MCP 管理指令

你不需要每次都手動打開編輯器改 JSON，Claude Code 提供了完整的 CLI 子指令：

CLI 指令 功能說明 實戰範例
claude mcp 列出當前所有已載入的 MCP Server 連線狀態與註冊的 Tools 清單 claude mcp
claude mcp add <name> -- <cmd> 快速將 MCP Server 註冊到專案配置中 claude mcp add brave -- npx -y @modelcontextprotocol/server-brave-search
claude mcp reconnect <name> 若 Server 進程崩潰或更新了代碼，強制重啟並重新握手 claude mcp reconnect postgres
claude mcp disable <name> 暫時停用指定 Server，避免佔用 Token 或衝突 claude mcp disable github
claude mcp login <name> 觸發瀏覽器 OAuth 授權（如 Sentry、Google Drive） claude mcp login sentry

社群目前已有超過數千個開源 MCP Servers。以下為軟體工程師、DevOps 與全端架構師精選的 8 大核心生產力 Servers：

Server 名稱 核心能力 (Tools / Resources) 典型應用案例
1. Filesystem
@modelcontextprotocol/server-filesystem		 指定目錄的沙盒化精準檔案存取、目錄樹掃描、二進位檔案分析 限制 Claude 只能存取指定子資料夾，防止誤改根目錄敏感檔案

4. Brave Search
@modelcontextprotocol/server-brave-search		 即時外網搜尋、技術文件檢索、API 規格最新變動查詢 「查一下 Next.js 15.2 最新版的 Server Actions 破壞性變更與解法」

7. Docker / K8s

05. 手把手實戰：從零開發自定義 MCP Server (Python & TS)

很多時候，企業內部有自己的微服務或特殊的 CI/CD Pipeline。自己寫一個 MCP Server 其實非常簡單！以下展示 Python (FastMCP) 與 TypeScript 兩種主流寫法。

5.1 使用 Python FastMCP：打造伺服器健康檢測與內部查詢 Server

官方推薦使用 fastmcp（極致輕量、裝飾器導向的框架，類似 FastAPI）：

# server.py — 企業內部維運與伺服器健康度 MCP Server
import psutil
import socket
from fastmcp import FastMCP

# 初始化 MCP 服務
mcp = FastMCP("DevOps-Ops-Server")

@mcp.tool()
def get_system_metrics() -> dict:
    """獲取本機系統資源負載率，包含 CPU 使用率、RAM 剩餘容量與磁碟空間"""
    return {
        "cpu_percent": psutil.cpu_percent(interval=1),
        "ram_used_percent": psutil.virtual_memory().percent,
        "ram_available_gb": round(psutil.virtual_memory().available / (1024**3), 2),
        "disk_free_gb": round(psutil.disk_usage("/").free / (1024**3), 2),
    }

@mcp.tool()
def ping_internal_service(host: str, port: int) -> dict:
    """測試指定內部微服務節點的 TCP 埠是否連通與響應延遲"""
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.settimeout(2.0)
    try:
        sock.connect((host, port))
        sock.close()
        return {"status": "UP", "host": host, "port": port}
    except Exception as e:
        return {"status": "DOWN", "host": host, "port": port, "error": str(e)}

@mcp.resource("system://hostname")
def get_hostname() -> str:
    """提供當前機器的 Hostname 靜態 Context 資源"""
    return socket.gethostname()

if __name__ == "__main__":
    mcp.run() # 預設以 stdio 模式執行

接著在 .mcp.json 加入該 Server：

{
  "mcpServers": {
    "my-ops": {
      "command": "python",
      "args": ["/Users/username/scripts/server.py"]
    }
  }
}

5.2 使用 TypeScript SDK：打造代碼品質合規審核 Server

// server.ts
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { CallToolRequestSchema, ListToolsRequestSchema } from "@modelcontextprotocol/sdk/types.js";

const server = new Server({
  name: "code-compliance-checker",
  version: "1.0.0"
}, {
  capabilities: { tools: {} }
});

server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: "check_license_header",
        description: "檢查檔案是否包含公司規定的 Apache 2.0 授權聲明標頭",
        inputSchema: {
          type: "object",
          properties: {
            filePath: { type: "string", description: "檔案相對路徑" }
          },
          required: ["filePath"]
        }
      }
    ]
  };
});

server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === "check_license_header") {
    // 執行檢查邏輯...
    return {
      content: [{ type: "text", text: "✓ 該檔案符合企業授權規約" }]
    };
  }
  throw new Error("Tool not found");
});

const transport = new StdioServerTransport();
await server.connect(transport);

06. Skill 深度實戰：打造自定義 Slash Commands 工作流

如果說 MCP 是賦予 Claude 連接外部系統的「手與腳」，那麼 Skill 就是將工程團隊日常的最佳實踐沉澱為一鍵觸發的「肌肉記憶」。

在 Claude Code 中，使用者可以輸入斜線指令（Slash Commands，例如 /review、/commit、/migrate），Claude 會立刻加載預設的高品質執行邏輯。這比每次手動在 Prompt 裡敲落落長的要求高效百倍！

6.1 Skill 的檔案結構與目錄規範

Claude Code 遵循標準的目錄約定：

專案目錄/
├── .claude/
│   ├── skills/
│   │   ├── code-review/
│   │   │   └── SKILL.md       # 觸發指令：/code-review
│   │   ├── git-commit-flow/
│   │   │   └── SKILL.md       # 觸發指令：/git-commit-flow
│   │   └── db-migrate-check/
│   │       └── SKILL.md       # 觸發指令：/db-migrate-check
│   └── settings.json          # Hooks 設定檔

若希望 Skill 在本機所有專案共用，可將資料夾建在 ~/.claude/skills/ 全域目錄下。

6.2 SKILL.md 的 YAML Frontmatter 規範

每個 SKILL.md 頂部必須包含標準的 YAML Frontmatter：

---
name: code-review
description: 對專案中所有已暫存或未提交的代碼變更進行全維度架構審查。當使用者輸入 /code-review 或要求審查代碼時觸發。
parameters:
  - name: level
    type: string
    description: "審查嚴格程度：'strict' (全面深究架構與邊界) 或 'fast' (僅檢查致命 Bug)"
    default: "strict"
---

6.3 生產級實戰範例：/code-review 企業級代碼審查 Skill

將以下內容儲存於 .claude/skills/code-review/SKILL.md：

---
name: code-review
description: 全維度架構與安全代碼審查流水線。自動分析 git diff，依資安、架構、效能、可維護性輸出結構化報告。
---

# /code-review — 企業級代碼品質審查流程

## 🎯 執行目標
當此指令觸發時，請依序嚴格執行下列步驟，切勿跳步：

1. **獲取變更內容**：
   - 執行 `git diff HEAD --name-only` 列出所有變動檔案。
   - 若無任何變動，提醒使用者並結束。
   - 排除自動生成檔案（如 `package-lock.json`, `dist/*`, `*.min.js`）。

2. **深度審查維度 (Four Pillars of Review)**：
   - 🚨 **安全性 (Security)**：是否存在 SQL Injection、XSS、未加密敏感資訊、過度寬鬆權限、未校驗的用戶輸入。
   - ⚡ **效能與資源 (Performance)**：是否存在 N+1 查詢、記憶體洩漏、未釋放連線、重複計算。
   - 🏛️ **架構設計 (Clean Architecture)**：是否符合 SOLID 原則、單一職責、錯誤處理完整度（禁用空 catch）。
   - 🧪 **測試完整度 (Testability)**：關鍵業務邏輯是否有對應的單元測試覆蓋。

3. **輸出結構化報告格式**：

```markdown
## 🔍 Code Review 總評分：[A / B / C / F]

### 🔴 Critical (必須立即修正，否則阻擋 Merge)
- **[檔案路徑:行號]**：問題具體描述。
  - 建議重構代碼：
    ```ts
    // 修復後範例
    ```

### 🟡 Warning (效能或壞味道建議改善)
- **[檔案路徑:行號]**：說明與改善建議。

```

07. 自動化防禦機制：Hooks 生命週期與事件攔截

很多工程師常常混淆 Skill 與 Hook：

Skill 是「你下達特定指令才會做的事情」；
Hook 是「不管你想不想，只要事件發生，就必定在後台默默執行的剛性保證」。

在 Claude Code 中，Hooks 定義在 .claude/settings.json。它支援在特定生命週期節點觸發自定義 Shell 指令：

Hooks 攔截與守護生命週期
Claude 決定調用工具 (例如: Bash: "git push -f origin main") │ ▼ ┌── PreToolUse Hook (指令攔截與安全檢查) │ 檢測到包含 "-f" 與 "main" ──► Exit 1 (強制中斷阻止危險操作) │ ▼ (若校驗通過) [ 執行 Tool ] │ ▼ ┌── PostToolUse Hook (執行後觸發) │ 檢測到編輯了 *.ts 檔案 ──► 自動執行 prettier --write 自動格式化 │ ▼ ┌── Stop Hook (Claude 回答完畢) └── 觸發系統桌面通知："Claude Code 任務已完成，請驗收！"

7.1 生產級 settings.json 配置範例

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "python3 -c 'import sys, json; data=json.load(sys.stdin); cmd=data.get("tool_input",{}).get("command",""); dangerous=["rm -rf /", "git push --force", "DROP DATABASE", ":(){:|:&};:"]; [sys.exit(1) for d in dangerous if d in cmd]'"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | xargs -I {} npx prettier --write "{}" 2>/dev/null || true"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification "Claude Code 已完成當前任務！" with title "Claude Code 提示"' 2>/dev/null || true"
          }
        ]
      }
    ]
  }
}

11. 常見踩坑排查與工程最佳實踐 (Troubleshooting)

在實際將 Claude Code 落地到企業開發時，團隊最常遇到的三大地雷與解法：

🚨 陷阱 1：MCP Server 啟動超時或 Failed to Connect

原因：在 .mcp.json 中使用 npx 時，如果遇到 npm 下載緩慢或網路超時，Claude Code 會在 10 秒後判定連線失敗。

解法：建議在本地全域預先安裝該 Server：npm install -g @modelcontextprotocol/server-postgres，然後在 .mcp.json 改用已安裝的可執行檔名稱，或使用速度快 10 倍的 Python uvx / uv 代替。

⚠️ 陷阱 2：Token 暴增與 Context Window 污染

原因：一口氣開啟了過多的 MCP Servers（例如開了 10 個 Server，共註冊了 80 個 Tools）。在每次對話發起時，所有 Tools 的 JSON Schema 都會被塞進 System Prompt，光初始 Context 就要吃掉 20k~40k Tokens！

解法：不要在全域設定裡掛載所有工具！每個專案只啟用當下需要的 2~3 個 Server。不常用者透過 claude mcp disable <name> 停用。

💡 陷阱 3：Slash Commands 未被辨識或 Skill 沒出現

檢查清單：

  1. 確認資料夾結構必須是 .claude/skills/<skill-name>/SKILL.md，注意檔案名稱必須大寫且為 SKILL.md；
  2. 確認 YAML Frontmatter 的 name 與資料夾名稱完全一致；
  3. 執行 /doctor 指令，檢查 Claude Code 對該設定檔的健康診斷日誌。
